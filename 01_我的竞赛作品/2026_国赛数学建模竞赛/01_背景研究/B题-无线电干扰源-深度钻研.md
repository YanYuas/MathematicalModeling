## 一、一句话定位（先记住这个）

**本题 = "带固定地点误差（±1°）的几何交会定位（Q1、Q2）+ 未知环境下机器狗的在线搜索—定位—清除决策（Q3、Q4）"。**

## 二、题设逐词点透（团队模板1，建模手写全解总览可直接复用）

| 词 | 字面意思 | 点透（为什么重要） |
|---|---|---|
| "已确定为一个半径1800米的圆形区域" | 搜索范围有界 | 覆盖网格、路径规划都在这个圆内做，任何源都在圆内任意位置 |
| "干扰源个数未知" | 不知道有几个 | 停止条件不能靠"数够了"，必须靠"频道全部确认空/已清除" |
| "示向度" | 检测点指向干扰源的最大场强方向方位角 | 是**带误差**的观测：同地点误差固定（重复测没用），全局误差在 ±1° 内 |
| "±1°误差" | 方向读数最多偏1度 | 距离1000米时横向偏差≈17.5米，接近清除半径20米，所以定位后必须逼近确认 |
| "有效接收半径1000–1500米" | 每个源能收到信号的最大距离 | 未知且接口不返回，覆盖设计必须按最坏的1000米做 |
| "交会定位法" | 多测点方向线交叉出区域 | Q1的模型：每条示向度是一个2°楔形角域，定位区域=所有楔形的交集（凸多边形） |
| "定位区域直径" | 区域内任意两点距离最大值 | 凸多边形直径在顶点对上取到，可用旋转卡壳 |
| "频道互不相同" | 一源一频道 | 频道是干扰源的天然ID，可用来管理"还剩哪些没清" |
| "频道切换1秒、检测5秒、移动5米/秒" | 每次动作的成本 | 平均定位清除时间的分子=这些成本的累加，优化就是减少总路程和无效检测 |
| "确保所有干扰源被清除" | 100%清除是前提 | 第一优先级，时间再短漏了源=失败 |
| "no_signal" | 收不到信号 | **不等于没有源**：可能是距离太远、频道已清、或（Q4）在定向源盲区里 |

**点透结论**：本题本质是"在只知道 20 个频道、圆域半径、动作成本的前提下，设计一套能证明'所有源都被清除'并尽量省时的在线搜索算法"；隐藏的三个决策点是——(1) 覆盖与扫描的成本-完备性权衡、(2) 定位误差（±1°、20米清除半径）下如何保证清除成功、(3) 什么时候可以安全地退出。

### 3.4 检测与清除的关键判据

| 结果 | 含义 | 处理 |
|---|---|---|

| `no_signal` | 收不到该频道信号 | 空频道 / 超接收半径 / 定向盲区，三者无法区分 |
| `clear→success` | 20米范围内发现目标并清除 | 同一源只清一次 |
| `clear→no_target_in_range` | 20米内无目标（或已清除过） | 无效动作，耗时3秒 |

### 3.6 接口规则（编程手必看，附件2要点）

- 地址 `http://127.0.0.1:2026`，仅本机回环；4 条指令：`/enter` `/measure` `/clear` `/exit`，全部 POST + JSON。
- 必填字段：`arena_id="default"`、`robot_id=参赛队号`、`request_id`（会话内幂等键）。
- 每个新动作用**新 request_id**；只有网络中断重试**完全相同**的动作才复用原内容原ID。

- 同时检查 HTTP 状态和 `accepted`；`accepted=false` 表示动作没生效，此时 `virtual_time_s=0` 不是当前时刻。
- `position.x/y` 必须有限数值，绝对值≤2000000；`channel` 必须 1–20 整数。
- 日志：正式测试结束后模拟器生成加密行为日志自动上传（≤2MB），从模拟器导出、**不要改文件名**，放支撑材料。

## 五、Q1 深度分析：交会定位区域直径与圆覆盖问题

### 5.1 题意

已知若干个检测点坐标 `S1...Sn` 及某干扰源 G 关于这些检测点的示向度 `θ1...θn`（各带 ±1° 误差），求：
1. 交会定位法计算**多边形定位区域直径**（区域内任意两点距离最大值）的算法；
2. 以定位区域直径为直径的圆**能否覆盖**定位区域。

### 5.2 数学化

- 每个检测点 `Si` 的示向度 `θi` 给出一个**2°楔形角域**：顶点在 Si、方向为 θi−1° 到 θi+1° 的两条边界射线之间（无限延伸的楔形）。
- **定位区域 = 所有楔形角域的交集** ∩（必要时与目标圆域求交以截断）。
- 楔形是凸集，凸集交集是凸集 ⇒ 定位区域是**凸多边形**（无退化时）。
- 真实干扰源 G 同时满足所有约束，所以数据合理时交集非空。

### 5.3 直径算法（可执行步骤）

输入：`{(Si, θi)}, i=1..n, n≥2`；误差半角 ε=1°。

1. 对每个 i，生成两条边界射线：`r_i^+`：`Si + t·u(θi+ε)`，`r_i^-`：`Si + t·u(θi−ε)`，t≥0。
2. 对所有**边界射线两两求交点**（射线与射线，非平行才有交）：
   - 射线 `P = A + t·u`、`Q = B + s·v`，解 `A + t·u = B + s·v`（2×2线性方程组），要求 t≥0、s≥0。
3. **保留同时落在所有楔形角域内的交点**（用每个楔形的两条边界做点在角域内判断），这些交点就是定位多边形的候选顶点。
4. 对候选顶点求**凸包**（Graham扫描 / Andrew单调链）得到定位多边形 P。
   - 特殊情况：交点数 <3 或为空 → 报告退化（无界或空集）；为稳健可将 P 与目标圆域 D(0,1800) 求交（线段裁剪），也可直接说明"真实数据应非退化"。
5. **直径 = max{ |p−q| : p,q 为 P 的顶点 }**。
   - 理由：凸多边形上最远点对一定在顶点对上。
   - 实现：顶点数 m 很小时（m ≤ 2n，本题规模极小）直接 O(m²) 暴力即可；论文中写**旋转卡壳**（Rotating Calipers）O(m log m) 更专业。
6. 输出：定位区域多边形顶点、直径 D、直径端点对。

### 5.4 "以直径为直径的圆能否覆盖"——答案：**不能保证（需要反例）**

- 若取"以直径两端点为直径端点的圆"（半径 D/2），**不能保证覆盖整个多边形**。
- **标准反例：等边三角形**。边长为 a，直径 D = a。以 D 为直径的圆半径 = a/2；而等边三角形外接圆半径 = a/√3 ≈ 0.577a > 0.5a，第三个顶点在圆外 ⇒ 覆盖失败。
- 结论写法：**一般情况下不覆盖**；只有特殊形状（如直径端点就是区域最远两点且其余点都在该直径圆内）才覆盖。
- 改进：若需要"能覆盖的圆"，应求**最小包围圆**（最小覆盖圆，Welzl 随机增量法 O(n)），其半径 ≥ D/2，当且仅当多边形退化到某条直径上时两者相等。
- 论文卖点：明确指出"直径 ≠ 最小包围圆直径"是本题埋的几何陷阱，用反例+最小覆盖圆给出完整回答。

### 5.5 陷阱

| 陷阱 | 说明 | 对策 |
|---|---|---|
| 误以为"直径相同必覆盖" | 直径是两点距离，圆覆盖是全体点约束 | 用等边三角形反例 |
| 交点全保留 | 不是所有射线交点都是顶点 | 必须过滤"在所有楔形内"的点 |
| 无界/空集 | 示向度近平行或无解 | 报告退化；可加圆域截断 |
| 角度跨0° | θi=359° 与 θi=1° 相邻 | 用弧度、处理角差取 min(|Δ|, 360−|Δ|) |
| 直径漏算 | 只算相邻点 | 顶点对全算或旋转卡壳 |

## 六、Q2 深度分析：第二检测点选择策略与候选区域

### 6.1 题意

已知某**全向**干扰源在一个检测点 S1 处测得的示向度 θ，选择第二个检测点 S2，使定位效果好，并给出 S2 的**候选区域**。

### 6.2 建模要点

- **精度度量**：复用 Q1——定位区域直径越小，定位越好。两测点交会角（S2 处对 G 的张角）越接近 90°，误差区域越小（误差在基线方向被放大）。
- **可探测性约束**：S2 必须能收到 G 的信号 ⇒ `|S2 − G| ≤ R`，但 R∈[1000,1500] 未知，**按最坏情况取 R=1000 米**做鲁棒设计。
- **位置约束**：G ∈ 楔形 `W(θ±1°)` ∩ 目标圆域；G 距 S1 的距离未知（0 到 3600 米都可能）。
- 移动成本：Q2 只问"定位效果"，但顺带说明 S2 不宜太远（为 Q3 省移动时间）。

### 6.3 推荐策略（可直接写进论文的路线）

1. 记示向度中线的单位方向 `u=(cosθ, sinθ)`，垂直方向 `v=(−sinθ, cosθ)`。
2. 先估计干扰源距离 Ĝ：S2 必须满足 |S2−Ĝ| ≤ 1000（最坏接收）；因此 Ĝ 距 S1 较近时 S2 可留在 S1 附近做垂直偏移，Ĝ 较远时 S2 需沿示向度方向先推进、再侧移；
3. 候选区域（主要情况）：
   **S2 = S1 + λ·v，λ ∈ [300, 800] 米**（两侧对称），并校验 `|S2 − Ĝ| ≤ 1000`，其中 Ĝ 是 G 的估计位置（取示向度中线与圆域交点或距离估计 d̂）。
   - 为什么下限 300：交会角太小定位差（φ≈arctan(λ/d̂)，λ 太小→φ小）。
   - 为什么上限 800：保证 S2 与 G 的距离在 1000 米以内（当 d̂ ≤ 800 时），且移动成本可控。
4. 若判断 G 距 S1 较远（例如在 S1 处距离未知但源可能在 1000 米外）：先把 S2 沿 u 方向推进到距 Ĝ 约 600–800 米处，再做垂直偏移。
5. 数值示例（示意）：S1=(0,0)，θ=0°（源在东侧）。取 S2=(0,600)：若 G=(600,0)，交会角 φ=atan(600/600)=45°，|S2−G|≈849 米 ✓；若 G=(300,0)，φ≈63°，|S2−G|≈671 米 ✓。注意 |S2−G|=√(600²+d²)，最坏接收要求 d≤800；若源更远（d̂>800），S2 应沿示向度方向先推进再侧移。

### 6.4 候选区域的严谨表述（论文公式化）

```
候选区域 A(S2) = { S1 + a·u + b·v : |b| ∈ [b_min, b_max], 
                   a ≥ 0, 且 |S2 − Ĝ| ≤ 1000, 且 S2 与 S1 对 Ĝ 的交会角 ∈ [30°, 90°] }
其中 Ĝ = S1 + d̂·u（d̂ 为干扰源距离估计，可取示向度中线与目标圆域边界的距离的 0.5~0.7 倍）
b_min≈300, b_max≈800（示意参数，演练中可调）
```
再加一句：当后续获得更多示向度时，用 Q1 的定位区域中心更新 Ĝ，S2 沿使交会角最大化的方向调整——即 Q2 的规则天然嵌入 Q3/Q4 的"交叉定位—逼近"循环。

### 6.5 论文卖点

- 把"定位效果好"落实到 Q1 的**直径指标**上，形成 Q1→Q2 的闭环；
- 引入**最坏接收半径 1000 米**的鲁棒约束，体现对未知参数的严谨处理；
- 候选区域用参数化表达式给出，方便编程手实现和演练调参。

## 七、Q3 深度分析：全向干扰源自动搜索、定位与清除（主战场）

### 7.1 问题本质

在**完全未知**（源数 10–16、位置、频道、接收半径 1000–1500）的 1800 米圆域内，控制一只机器狗完成"发现→定位→清除→确认清完"。数学上是一个**部分可观测的在线搜索/决策问题**（POMDP 风格），规模小（≤20 频道、≤16 源），现实约束宽松（虚拟 100 小时），所以**启发式确定性策略 + 完备性论证**是正路，不需要复杂强化学习。

### 7.2 指标口径（先钉死，防论文被扣分）

- 被清除比例 = 被清除个数 / 干扰源总数（演练时模拟器会给总数；**正式测试不显示真值**，按策略自判填写：若策略完备，清除数=总数，比例=100%）。
- 平均定位清除时间 = 定位清除总时间 / 被清除个数，其中**定位清除总时间 = 最终 `virtual_time_s`**（= 移动+换频+检测+光学定位+清除的累加；/enter、/exit 不耗时）。
- 表1（问题3正式测试结果）四列：**测试案例编码 | 清除干扰源个数 | 平均定位清除时间 | 程序运行时间**（程序运行时间=现实时间，/enter 到结束，用本地时钟或 `real_timestamp_ms` 算）。

### 7.3 核心矛盾

1. **覆盖 vs 成本**：任何源可能在圆内任意位置，接收半径最坏 1000 米 ⇒ 要"发现"全部源，检测点必须覆盖整个圆域；覆盖点越多越稳但越慢。
2. **误差 vs 清除半径**：±1° 误差在 1000 米处横向偏 17.5 米、1500 米处 26 米，接近/超过清除半径 20 米 ⇒ 交叉定位后**必须渐进逼近**，靠 `near→clear` 保证成功。
3. **停止条件**：不知道总数 ⇒ 只有"所有 20 个频道要么被清除、要么被确认空（全网格 no_signal）"才能放心退出。

### 7.4 推荐策略框架（五阶段循环）

```
阶段0 侦察覆盖网格
  在圆域内布检测点网格（正三角形格点，推荐间距 1500 米，最大空隙 1500/√3≈866 米 < 最坏接收半径 1000 米），
  保证圆内任意源至少被一个网格点罩住；1800 米圆域约需 7~9 个点（d=1200 时约 10~12 个）
   ⇒ 任何源都至少被一个网格点"罩住"
阶段1 频道发现
  在每个网格点扫 20 频道（每点成本：换频 19×1 + 检测 20×5 = 119 秒）
  记录每个频道的 direction / no_signal 历史
阶段2 交叉定位
  某频道在两个不同点测到 direction → 用 Q1 方法求定位区域 → 取中心为估计点 Ĝ
阶段3 渐进逼近（homing，关键）
  从当前点沿示向度方向走一段（如 200~300 米）→ 停下 /measure：
    - direction → 更新示向度，继续沿新方向走
    - near → 目标已在 5 米内 → 原地 /clear（必成功）
    - no_signal → 距离超接收半径或方向被干扰，退回上一检测点附近重新走
  直到 clear=success
阶段4 收尾确认（保证100%）
  剩余"从未 signal 过"的频道 = 疑似空频道，在全部网格点补测；
  若某频道在某点意外 signal → 转阶段2/3；
  所有剩余频道在全部网格点 no_signal → 判定为空频道
阶段5 退出
  全部 20 频道 ∈ {已清除} ∪ {已确认空} → POST /exit
```

### 7.5 关键机制详解

**（1）覆盖网格设计**
- 正三角形格点间距 d，任意点到最近格点的最大距离 = d/√3 ≈ 0.577d。
- 要求 0.577d ≤ 1000 ⇒ d ≤ 1732。推荐取 d=1500 米（最大空隙 866 米，留 134 米裕量）：六边形单元面积 (√3/2)d²，圆域面积/单元面积 ≈ 5.2，加边缘修正约需 **7~9 个点**；想更密可 d=1200（约 10~12 个点）。
- 论文中给出：网格间距选择、覆盖半径证明（"任意源至少被一个检测点覆盖"）。

**（2）扫描成本预算（示意估算，供论文表格）**

| 项 | 数量 | 单位成本 | 小计 |
|---|---|---|---|
| 全网格频道扫描 | ~9 点 × 20 频道 | 5 秒/次 | ~900 秒 |
| 换频 | ~180 次 | 1 秒 | ~180 秒 |
| 移动（网格路径+逼近） | ~4000~8000 米 | 5 米/秒 | ~800~1600 秒 |
| 定位+逼近+清除 | ~16 源 × 100~150 秒 | — | ~1600~2400 秒 |
| **合计（虚拟）** | | | **≈ 3500~5000 秒（约 1~1.5 小时）** |

→ 平均定位清除时间 ≈ 3500/13 ≈ 270 秒 至 5000/13 ≈ 380 秒（约 5~8 分钟量级）。演练时通过**在覆盖裕量内加大网格间距（减少点数）、优化路径（zigzag/TSP/2-opt）、减少无效清除**继续压。

**（3）homing 收敛性（论文论证点）**
- 每步测得的示向度误差 ≤1°；沿示向度走 200~300 米后重新测量，方向修正量 ≥ 偏差量（误差是固定的同一地点误差？注意：**每走一段就是一个新地点**，误差重新抽取；跨地点误差在 ±1° 内），每一步都缩小与源的距离，最终进入 5 米内触发 `near`。
- 只要初始点在接收半径内（网格保证），纯追踪式逼近对全向源**收敛**。

**（4）停止条件与完备性（论文最亮的部分）**
- 断言：若 (a) 网格覆盖保证任意源 ≤1000 米内有检测点；(b) 对每个频道，要么被清除，要么在所有网格点 no_signal——则所有干扰源必被清除。
- 证明思路：若有源未被清除，它属于某个未清除频道，且它在圆内 ⇒ 存在网格点距它 ≤1000 米 ⇒ 该点测该频道应得 direction/near（全向源无盲区），与 (b) 矛盾。
- 这是 Q3 能写"清除比例=100%"的底气，也是与 Q4 的关键差异（Q4 有盲区，完备性变难）。

**（5）优化方向（按性价比排序）**
1. 路径规划：网格点间用蛇形/螺旋扫描，逼近目标时顺路扫频道（信息复用）。
2. 频道管理：已清除频道不再测；先集中清"已发现"频道，再处理"疑似空"频道（多数频道有源，别一开始就把空频道全网格扫一遍）。
3. 无效清除控制：clear 失败（no_target_in_range）耗时 3 秒且暴露信息少，只有估计误差 <20 米才尝试 clear；否则继续 measure 逼近。
4. 早期停止试探：演练中统计"网格覆盖到第几层就能发现全部源"，调网格密度。

### 7.6 编程要点（Q3 程序）

- 串行请求循环 + request_id 管理（新动作新ID、重试复用、不并发）。
- 用 `/enter` 响应的 `remaining_real_duration_s` 做现实超时保护（比如预留 60 秒收尾）。
- 本地记录：每个频道的状态机（未发现/已定位/逼近中/已清除/确认空）、每个检测点的结果、总虚拟时间。
- 所有判断用英文结果码字符串（`direction/near/no_signal/success/no_target_in_range`），不要依赖界面中文。
- 正式测试前确认日志 <2MB（避免异常高频循环）。

### 7.7 Q3 陷阱清单

| 陷阱 | 后果 | 对策 |
|---|---|---|
| 同点重复检测 | 误差固定不变，白费 5 秒 | 永远换地点再测 |
| 以为 no_signal=空频道 | 漏掉距离远的源 | 覆盖网格 + 全点确认 |
| 定位完直接 clear | ±1°误差可能超 20 米清除半径 | 渐进逼近到 near 再 clear |
| 假设每频道都有源 | 浪费在空频道上 | 频道状态机管理 |
| 用现实时间算平均定位清除时间 | 口径错误 | 分子用最终 virtual_time_s |
| 提前退出 | 漏源、比例<100% | 完备性停止条件 |

## 八、Q4 深度分析：全向 + 定向混合源（难点升级）

### 8.1 新增难点

1. **定向源盲区**：定向源只覆盖定向方向 ±90°（180°扇区）。检测点在盲区内测不到，即使距离很近。
2. **no_signal 三重原因无法区分**：空频道 / 超接收半径 / 定向盲区。某频道"看起来空"可能是盲区漏检。
3. **数量与定向方向都未知**。
4. 好消息：**清除不受方向限制**（≤20 米即可），所以"发现+定位"是唯一难点。

### 8.2 关键理论观察

- 若某检测点 P 测到某频道 `direction`，则 P 在定向源的覆盖扇区内；沿示向度方向向源走，新点仍在扇区内（向量 G→P 与 G→P′ 同向），**homing 对定向源同样收敛**——所以"一旦发现就能清掉"。
- 难的是"发现"：从圆内某点看，定向源把 180° 扇区亮出来，其余 180° 是盲区。**静态网格存在死角**：例如源在圆周 (1800,0) 处朝正东（向圆外发射），圆内所有网格点都在它背后 ⇒ 全部 no_signal。所以**没有简单静态网格能保证发现所有定向源**，必须引入"多方位观测"。

### 8.3 推荐策略（在 Q3 框架上扩展）

```
Q3 全部阶段照跑（发现并清除所有能被发现的源，包括从扇区里测到的定向源）
+
新增 阶段4' 多方位确认（针对"从未 signal 过"的频道）
  对每个疑似空频道：
    - 在第一轮网格点已 no_signal 的基础上，追加"方位多样性"检测：
      在圆域内绕圆心取 8~16 个不同方位的点（如半径 900/1400 的两圈）补测；
      任何一个点测到 direction/near → 该频道有源 → 交叉定位 + homing 清除
    - 全部方位点仍 no_signal → 判定空频道
新增 停止条件升级
    - 无法数学保证 100%（存在极端定向源死角），改为：
      概率完备性论证 + 演练清除率验证（论文明说，评阅更信任坦诚）
可选 兜底策略
    - 若时间预算充裕，对"嫌疑频道"（历史上曾 signal 但未清完、或位置在边缘的频道）绕 360° 巡逻一圈
```

### 8.4 论文论证点（Q4 卖点）

- **发现概率分析**：定向源覆盖 180°，若从 k 个方位角近似均匀分布的检测点观测且源方向均匀随机，则至少一个点落入扇区的概率 = 1 − (1/2)^k（独立近似）。k=8 时 ≈ 99.6%（示意模型，需说明假设）。
- 定向源"一旦发现即可清除"（homing 收敛 + 清除与方向无关）——把问题收窄到"发现"。
- 完备性降级声明：静态网格对圆周边缘、朝圆外发射的定向源存在理论死角，用多方位巡逻缓解，并用演练统计（清除率、平均时间）作为有效性证据。

### 8.5 Q4 额外陷阱

| 陷阱 | 后果 | 对策 |
|---|---|---|
| 把 no_signal 当空频道 | 漏掉盲区里的定向源 | 多方位确认 |
| 认为定向源清不掉 | 放弃治疗 | homing 进入扇区后照常清除 |
| 忽略"近但盲" | 走近了也 no_signal，以为没源 | 记住：no_signal 不证明无源 |
| 网格死角的极端案例 | 理论完备性被推翻 | 论文主动声明 + 概率论证 + 巡逻兜底 |
