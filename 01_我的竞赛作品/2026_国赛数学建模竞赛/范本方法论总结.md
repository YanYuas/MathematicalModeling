# 国赛范本方法论总结

> 从2026国赛B题（无线电干扰源定位与清除）中提炼的可复用经验
> 整理时间：2026-09-18
> 适用场景：数学建模竞赛三手分工协作

---

## 一、三手分工体系

### 1.1 角色定位

| 角色 | 核心职责 | 产出物 | 目录 |
|------|---------|--------|------|
| **建模手** | 问题分析、模型假设、公式推导、算法设计 | 每问九件套+移交包 | 02_建模手/ |
| **编程手** | 算法编码、实验验证、模拟器对接 | 可运行代码+实验结果+验证报告 | 03_编程手/ |
| **论文手** | 组织方案、正文撰写、图表排版、参考文献 | 论文正稿+配图+AI声明 | 04_论文手/ |
| **总控** | 进度同步、数据权威、冲突协调 | 任务总控文档 | 00_任务总控/ |

### 1.2 协作机制：移交—反馈—闭环

```
建模手完成建模 → 打包移交包（00-移交说明.md）
    ↓
编程手按清单实现 → 发现问题写反馈（理论问题反馈.md）
    ↓
建模手融入反馈 → 更新权威数字表
    ↓
论文手开始写作 → 数字以权威数字表为准
```

**关键纪律**：
- 编程手不自行改模型假设，有问题先反馈
- 所有人引用数字以`00_任务总控/权威数字表.md`为准
- 每问完成后必须有联合校验

## 三、编程手工作规范

### 3.1 每步【思路】标注

代码中每一步都要写为什么这么做，而不是做了什么：

```python
# 【思路】用B*-Tree表示布局，因为可以O(n)计算面积
class BStarTree:
    ...
```

### 3.2 验证题机制

- 建模手提供已知答案的验证题
- 编程手必须先跑验证题，答案对了再跑正式数据
- 验证题不对 → 查bug，不硬跑正式数据

### 3.3 多次运行取最优

- 随机算法至少跑10次，取最优结果
- 固定随机种子，保证可复现
- 关键数据写入`00_任务总控/权威数字表.md`

### 3.4 代码组织结构

```
03_编程手/
├── Q1/Q2/Q3/Q4/     每问独立编程
├── MATLAB_Framework/  最终实现（含logs运行记录）
├── 图表库/            图件+出图脚本
├── 代码库/            可复用核心代码
├── 核验脚本/          验证脚本
└── 交付文档/          操作手册、框架说明
```

## 四、论文手工作规范

- 语义化版本：v主版本.次版本.修订
- 推翻结论升主版本，加内容升次版本，改错字升修订

- 最终版放在`06_交付物/`顶层

### 4.2 配图规范

- 命名格式：`图X.Y-Z_描述_v版本.png`
- 图件按问存放在`04_论文手/QX/配图/`
- 跨问配图索引放在`04_论文手/论文配图/`

### 4.3 AI工具使用声明

- 必须提交AI工具使用声明（比赛要求）
- 详细记录使用了哪些AI工具、做了什么

## 九、常见坑与避坑指南

### 9.1 建模手常见坑

1. **假设不系统化**：必须列H1-Hn，每个假设说明依据
2. **陷阱不分级**：T级（题设陷阱）+ M级（建模陷阱）
3. **验证题缺失**：必须给编程手提供已知答案的验证题
4. **数字不统一**：所有数字以权威数字表为准

### 9.2 编程手常见坑

1. **跳过验证题**：验证题不对就跑正式数据，结果不可信
2. **不写思路注释**：只写代码不写为什么，自己都看不懂
3. **只跑一次**：随机算法必须跑多次取最优
4. **自行改模型**：发现问题先反馈，不自行改假设

### 9.3 论文手常见坑

1. **数字对不上**：必须以权威数字表为准
2. **配图不清晰**：300dpi以上，标注完整
3. **版本混乱**：语义化版本管理，历史版本归档
4. **AI声明遗漏**：比赛要求必须提交AI使用声明

## 十一、本次国赛的特殊经验

### 11.1 模拟器对接

- Q3/Q4需要与模拟器通过HTTP+JSON通信
- 必须有完整的测试操作手册
- 正式测试有严格时间窗口，提前演练
- 自记录日志和加密日志都要保留

### 11.2 多实现并存

- Python和MATLAB两套实现并存
- 主次未定时，两套都保留，加冲突说明
- 最终选定MATLAB作为Q3/Q4的正式实现

### 11.3 备选题目研究

- 比赛初期同时研究A题和B题
- A题（充电站选址定价）的研究成果归档保留
- 最终选择B题（无线电干扰源定位）
