## 一、版本号格式：语义化版本（SemVer）

所有**内容型文档**（正稿、组织方案、建模文档、清单、报告、数字表）统一用三段式：

```
v<主>.<次>.<修订>       例：v1.2.0、v0.9.1
```

| 段 | 什么时候升 | 例子 |
|---|---|---|
| **主版本** | 结论/结构重大变化：整表结论推翻、章节重构、新增一问、交付物类型变化 | 正稿 v1.0.0（初稿）→ v2.0.0（结论修正重写） |
| **次版本** | 新增内容：新章节、新图表、回填实测数据、新增算例 | 正稿 v1.0.0 → v1.1.0（回填扫描实测） |
| **修订** | 小修：错别字、格式、单点数字修正、图号统一 | 正稿 v1.1.0 → v1.1.1（改错别字） |

可选后缀：`-rc`（候选定稿）、`-final`（定稿）。废弃文档用 `-废弃` 标注并移入 `99_归档/`。

**判定口诀**：推翻了就升主版本，加了内容升次版本，改了错字升修订。

## 二、文档头部元数据块（每个交付文档必带）

所有内容型文档在**标题下方**写统一元数据块：

```
> 版本：v1.2.0 | 更新：2026-09-11 | 状态：🔄进行中（✅定稿/🔄进行中/📝草稿）
> 变更：v1.2.0 回填参数扫描实测；v1.1.0 新增三侧审计结论；v1.0.0 初稿
```

- 版本号永远写**当前版本**（一个文档只有一个当前版本）
- `变更`行按时间倒序列出**最近 3 条**（更早的进 CHANGELOG）
- 状态是给全队看的"能不能引用"：**✅定稿**=可放心引用；🔄进行中=引用前先看变更行；📝草稿=仅供讨论

## 三、文件命名规则（防止多副本混乱）

1. **正文文档的文件名一律不带版本号**（版本在头部管理），如 `正稿.md`、`论文组织方案.md`。
2. 只有**对外提交/快照**才在文件名带版本号，如 `正稿_v2.0.0-final.md`，且该快照放入 `99_归档/旧版本/` 或 `06_交付物/`。
3. 不再使用 `v1`、`v2`、`V3`、`final2` 这类混搭写法。
4. 修改文档**直接改原文件**（升头部版本号），不要"另存为新文件"——多副本是版本混乱的最大来源。

### 三.1 ⚠️ 具名例外：`06_交付物/国赛论文*`（**本项目自定管理法，不得按常规推断**）

**队员 2026-09-12 说明**：这套文件用**我们独特的管理方法**——
**大版本先行**（把初稿/骨架做好），**小版本做精细的优化**。

| 规则 | 内容 |
|---|
| 🚫 **不要动** | `06_交付物/国赛论文*` 的**所有文件**（既不删、不合、不改名） |
| 🚫 **不要推断** | 不得按"文件名版本号大小"或"mtime 先后"判断哪份权威、哪份该归档 |
| ✅ 判据 | 大版本 = 初稿/骨架；小版本 = 精细化优化。二者**并存是设计，不是混乱** |

> **反例（本项目真实踩过）**：2026-09-12 总控按 mtime 与正文关键词命中，
> 判定「`国赛论文.docx` 内容最少 ⇒ 版本落后，`v2.0` 比 `v1.2.51x` 更旧 ⇒ 应合并」。

>
> **同源教训**（`实践反馈融入.md` **R1**）：**单点/单一指标不能外推为全局结论**。
> 版本判断同样如此——**一个指标（mtime）不足以定义"权威"**。

## 六、版本状态流转

```
📝草稿 → 🔄进行中 → ✅定稿 →（重大修改）→ 升主版本回到 🔄
                                        →（废弃）→ 移入 99_归档/ 标注 -废弃
```

- **定稿后若要改结论**：升主版本，改回"🔄进行中"，改完重新定稿，不许静默改定稿内容。
- **跨角色引用规则**：A 角色的文档被 B 角色引用前，B 须确认 A 文档状态 ≥ ✅（或记下引用时的版本号）。

## 九、归档纪律（2026-09-12 新增）

1. **活文档与历史件分家**：`00_任务总控/` **只放活文档**（每次盘点须更新者）。
   一次性历史件（审核报告、小结、启动提示词、已答复的发现单）一律入 `99_归档/`。
2. **每个归档目录必须有 `README.md`**：写明归档日期、归档人、来源、归档原因，以及**逐条处置对照**。
3. **归档件默认不可引用**：不得作为论文、交付物或支撑材料的依据。
   确需引用时（如 AI 合规证据链）须：① 写**新路径**；② 在归档 README 与 §八 登记"谁引用了它"。
4. **归档 ≠ 删除**（§五）：只移动、不改进内容；被证伪的结论保留原文与"已废弃/已更正"标注。
5. **目录命名统一 `类型_日期`**（如 `审核报告_2026-09-12`）。
   ⚠️ 现存 `Q1建模文档_迁移前旧版_2026-09-12/`、`Q1工作区说明_2026-09-12/` 为历史命名，**不追溯改名**（改名成本 > 收益），新归档一律按新规范。
6. **归档前必查引用**：`grep -rn "<文件名>"` 全库扫一遍，把活文档里的路径**当场改掉**，别留悬空引用。
