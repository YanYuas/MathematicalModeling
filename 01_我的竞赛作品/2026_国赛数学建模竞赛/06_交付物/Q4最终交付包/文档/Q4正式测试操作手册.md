# Q4 正式测试操作手册

2026-09-13

一句话：程序不是 exe。赛题只要求机器狗程序通过 HTTP+JSON 与模拟器通信，
语言和形态自选，附件 2 第 11 节同时给了 Python 版和 MATLAB 版示例。
本手册走 MATLAB 主线。

## 先破除三个误解

| 误解 | 事实 |
|---|---|
| 最终程序要编译成 exe | 赛题从未要求 exe。附件 2 第 11 节的官方示例就是脚本 |
| 改模拟器 exe 来调试 | 模拟器是赛题方的绿色软件，只能改端口（附件 1 第 4.4 节）。改它的判定逻辑会让正式测试作废，日志加密上传校验，成绩以此为准 |
| 队号写进代码方便 | 双重违规。附件 2 第 5.1 节要求 robot_id 逐字节等于当前登录队号（运行期），格式规范要求支撑材料隐去队号。所以本程序运行期传参，源码不含真号 |

## 一、交付物清单

| # | 内容 | 从哪来 |
|---|---|---|
| 1 | 机器狗程序 | 程序目录（MATLAB 源码） |
| 2 | 程序自行记录的指令序列与响应 | 程序自动写，自记录日志目录 |
| 3 | 三次正式测试的加密行为日志（不要改文件名） | 从模拟器界面导出，不是程序生成 |
| 4 | 论文表 1 四列 | 程序结束时打印的块里抄 |

模拟器加密日志上传上限 2 MB（附件 1 第 4.6 节）。程序结束时也会打印自记录日志体积，
用来核对有没有异常高频循环。

## 二、时间窗

    确认开始测试
      |
    模拟器准备案例数据 -> 显示 5 秒倒计时 -> 倒计时结束：开启 25 分钟窗口并开放接口
      |
    程序调用 /enter 成功 -> 开始算程序运行时间，最长 20 分钟
      |
    实际截止 = min(25 分钟窗口截止, /enter 成功后 20 分钟)

两条硬约束：

1. MATLAB 启动约 40 秒。必须在倒计时结束前就把 run_Q4.bat 启动起来并输完队号，
   否则倒计时一过程序才开始启动，/enter 会晚于窗口开始 5 分钟，实际可用时间不足 20 分钟。
   程序会把剩余时间打印出来提示。

2. /enter 响应里的 remaining_real_duration_s 是本局真实可用秒数（0 到 1200），
   程序已按它控制收尾（配置里预留 60 秒），不要假定每次都是 1200。

## 三、跑一次（演练和正式一样）

1. 启动模拟器，联网登录，选模块（问题 4 演练 / 问题 4 正式）
2. 先双击 run_Q4.bat，按提示输入：
   - robot_id：你的参赛队号，必须与模拟器当前登录队号逐字节一致
   - 测试案例编码：可留空，正式测试结束后从模拟器界面抄回来也行
   - 局数：直接回车等于 1
3. 回到模拟器，确认开始测试
4. 等 5 秒倒计时结束，程序会自动 /enter。接口没开时连接被拒，程序用原 request_id
   重试到开放为止，这是赛题要求的行为
5. 程序跑完自动 /exit，打印表 1 四列和日志路径

命令行等价做法：

    "D:\R2026a_Windows\bin\matlab.exe" -nosplash -sd "<程序目录>" -batch "main_Q3Q4('Q4','<参赛队号>')"

## 四、跑完看什么

程序结束时打印本局报告，其中第一块是表 1：

    测试案例编码     : 从模拟器界面抄
    清除干扰源个数   : N
    平均定位清除时间 : xxx.xx s    虚拟时间除以清除个数
    程序运行时间     : xxx.xx s    /enter 到结束的墙钟

第二块是本局读数，含虚拟时间的四项分解（移动、检测、切频、清除）、请求数、
已确认空的频道数。这些不进论文，供排查用。

然后到模拟器的日志列表里导出本局的加密行为日志，放支撑材料，不要改文件名。

## 五、日志

自记录日志在 自记录日志 目录下，每条请求一行 JSON，覆盖每一次请求，含失败的尝试：
seq、kind、wall_clock_ms、elapsed_wall_s、endpoint、attempt、request_id、
request_payload、response_payload、http_status、response_received、accepted、
virtual_time_s、transport_error、error_identifier。另有 session_start 和 session_end 两条。
满足附件 1 第 4.6 节与附件 2 第 12 节的要求。

注意：log_record 里 fopen 失败时报 -1，程序会跳过那一条而不报错。
所以程序运行期间不要读日志文件，跑完再读。

## 七、改代码时的红线

Q4 专属：

| 红线 | 理由 |
|---|---|
| 检测点集绝不可裁剪回圆域 | 裁掉外环，朝外的边界定向源就永远测不到，100% 清除的依据不成立 |
| 发现判据必须用 surrounding，不能沿用 1000-覆盖 | 一个点可以被圆盘罩住却永远看不见背对的源 |
| 末端判据用 /clear，不可等 near | 定向源盲侧贴到 1 m 也不返回 near，等下去就是死锁 |
| 构造 L 必须做扇区过滤 | 否则引入不存在的约束，L 缩到错误位置 |
| 不可混淆定向方向与示向度 | 语义相反、起点不同，混用符号全错 |
| 改动外环半径或点数后必须重跑 surrounding 自检 | 外环半径的可通过区间是 1870 到 1960 m |

承自 Q3：

| 红线 | 出处 |
|---|---|
| 同一 request_id 只能在重试完全相同的动作时复用，改内容即 HTTP 409 | 附件 2 第 5.3 节 |
| 不得并发发送不同动作，须逐次等完整响应 | 附件 2 第 1.4 节、第 12 节 |
| 必须同时检查 HTTP 状态码与 accepted | 附件 2 第 5.3 节 |
| accepted=false 时 virtual_time_s=0 不是当前虚拟时刻 | 附件 2 第 4.1 节 |
| 只有 measure_result="direction" 才读 svd_deg，且它含正负 1 度误差 | 附件 2 第 12 节 |
| /clear 不切换测向机频道，也不产生切换耗时 | 附件 2 第 1.3 节 |
| no_signal 不等于附近没有源，Q4 里它是三义的 | 附件 2 第 2.2 节 |
| 测试结束后不要调 /exit 查原因，接口已关 | 附件 2 第 9.3 节 |

## 八、已知的限制

1. webwrite 拿不到 HTTP 4xx 的 JSON 响应体。MATLAB 抛的是普通 MException，
   没有 Response 属性，只能从标识符里取状态码，服务端的 JSON 详情看不到。
   要完整 body 得改用 matlab.net.http.RequestMessage，改动较大，没做。

2. 程序无法知道本局干扰源总数，接口不返回。所以打印的清除比例分母来自本地状态机，
   是下界不是真值。论文表 1 不含这一列。

3. 检测点集在最坏情形下余量为 0：第三近邻的最大距离恰好等于有效接收半径 1000 m。
   设计条件卡在临界点上，靠的是判据取不超过而非小于。
