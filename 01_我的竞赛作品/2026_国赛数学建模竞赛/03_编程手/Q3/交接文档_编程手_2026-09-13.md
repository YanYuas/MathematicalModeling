## 三、与 Python 架构的对比整合

### 3.1 必须一致的（协议与口径，**不是实现**）

| 项 | 口径 |
|---|---|
| 端点 | 只有 `/enter /measure /clear /exit` 四条 |
| `arena_id` | `"default"` |
| `robot_id` | **逐字节等于当前登录队号**（运行期传参，源码不留真号） |
| `request_id` | 同一动作重试时**复用**；改内容即 409 |
| 并发 | **禁止**并发发不同动作（必须逐次等完整响应） |
| 双检查 | **同时**判 HTTP 状态码与 `accepted` |
| 坐标界 | `\|x\|,\|y\| ≤ 2e6`；`channel` 为 1~20 整数 |
| 时钟 | 目标用**虚拟时间**；硬约束是**现实时间 ≤ 1200 s**（`remaining_real_duration_s` 必读） |
| `svd_deg` | **只在 `measure_result == "direction"` 时存在**，且含 ±1° 误差 |
| `/clear` | **不切换**频道、不产生切换耗时；成功条件只看距离 ≤ 20 m（与朝向无关） |
| `no_signal` | **不等于**附近无源（可能超接收半径 / 定向盲区） |
| 判空 | 某频道**在全部检测点**都 `no_signal` 才能判空 |

### 3.2 可以逐位对比的「不变量」（**建议用这些对齐，而不是比路由结果**）

两边各自求最优，**路由顺序不该强求相同**。建议约定比这些：

| 不变量 | 怎么取 |
|---|---|
| 检测点集 `P` | 两边都用同一参数生成后直接比对坐标（Q3 径向：中心 + 6@1000 相0° + 6@1300 相30°） |
| 覆盖空隙 | 同一采样方案下应一致（生产档 **811.60 m**） |
| 频道状态序列 | 每个检测点上"测了哪些频道"的集合、以及状态推进时刻 |
| 检测次数分类 | **必要观测 / 待清重测 / 判空** 三类计数（§3.4 给了本侧的真机实测值） |
| `R_MEC` 与派发档 | 给定同一对观测，`R_MEC` 与"direct/sweep/homing"应一致 |
| 时间账 | `虚拟时间 = 移动 + 检测×5 + 切换×1 + 清除(成功5/失败3)`，**残差应为 0** |

### 3.3 已知的实现差异（**不是优劣**）

| 项 | MATLAB 侧 | Python 侧 |
|---|---|---|
| 角域求交 | `polyshape` 布尔交 | 射线两两求交 + 角域过滤 + Andrew 凸包 |
| 圆域截断 | `polyshape` 多边形∩圆（外切 720 边形） | 需同样处理，**两边都要真求交** |

### 3.4 一条必须更正的旧结论（**重要**）

早期登记过「79 案例互验一致，结论：该口径 Q3 不用 ⇒ 代码一行不改」。**那个判断是错的**：
Q3 走的恰恰是"截断"这条路，而当时的截断实现**只丢圆外顶点、不做边与圆求交** ⇒
细长交会区被削成退化多边形 ⇒ 估计半径假性偏小 ⇒ 清除派发到错误的档
（真机一局因此打了 **97 次** `/clear`）。

- 细节见 `Q3调优经验与补丁记录.md` **P-7**；已新增回归 `test_clip_to_domain.m`。
- **对整合的含义**：那 79 个案例没覆盖"深穿透圆域"的配置 ⇒ **不要**用"两实现互验一致"
  来论证几何内核正确。**要补的是覆盖该配置的用例。**

### 3.5 本侧真机实测的检测分解（**可作为对照基准**）

在 23 局生产档真机上逐局对账（`_analyze_real_runs.py` 可复现）：

| 类 | 次数 | 性质 |
|---|---|---|
| 必要观测（每源第 1、2 条） | **恰好 2.0 次/源** | 已是理论下界 |
| 待清频道重测 | 修前 26.5 次/局 ⇒ **修后 2~7 次/局** | 已压掉（见 P-5） |
| 判空（每空频道） | **恰好 13.0 次**（= 检测点数） | 已是理论下界 |
| 清除后仍在测 | **0** | 无缺陷 |

⇒ 若 Python 侧在这三项上有差异，说明**口径或状态机**不一致，而不是路由差异。

## 四、独立推进 Q4

### 4.1 Q4 = Q3 + 一条前提替换 + 两个新机制

| # | 改动 | 性质 |
|---|---|---|
| 1 | 源由全向 → **定向**（±90° 盲区） | **前提替换**：`no_signal` 由二义变**三义**；"覆盖 ⇒ 发现"失效 |
| 2 | 发现判据：覆盖 → **surrounding（凸包包含）** | 机制新建 |
| 3 | 清除层：新增/提级**扫掠清除** | 机制新建（补上中等 `R_MEC` 段） |

**唯一的几何新增**：`|∠((X−G),u)| ≤ 90° ⟺ (X−G)·u ≥ 0` ⇒ **扇区 = 闭半平面**（凸集）。
由此"任意朝向都保证发现" ⟺ `G ∈ conv Q(G)`（充要），这是 Q4 全部可解性的根。

### 4.2 现状（**诚实**）

| 项 | 状态 |
|---|---|
| Q4 断言 | **8/8 通过**（`run_assertions('Q4')`） |
| **端到端实跑** | 🔴 **零次** —— 完整的 阶段A→B→C→`/exit` **从未跑过** |
| 扇区探针 | 已实现于 `Q4_extensions.sector_probe()`，**`main_Q3Q4.m` 未调用**（未接线） |
| Q4 配图 | 0 张 |

### 4.3 两条硬设计条件（**有实测阈值，别改错**）

1. **外扩环带宽度 = `d`（不是 `d/√3`）**。`d/√3` 是**最近邻**覆盖半径，而 surrounding 需要
   「**三**最近格点」都在 `Q(G)` 内，而**第三近邻可达 `d`**。
   实测：宽度 `d/√3` ⇒ 全域失败 **2.47%**（边界带 **42.05%**）；宽度 `d` ⇒ **0.00%**。
   **注意**：`generate_triangular_grid` 里的 `margin` 与 `Q4_extensions` 都已用 `d`；
   **但 `sweep_clear_exact.m` 是旧版、不在主流程上，别被它误导**。
2. **设计条件 `d ≤ R_eff = 1000 m`**（原写 `d ≤ 1732.0508` 已作废）。
   实测阈值：`d ≤ 1000` → 0%；1050 → 1.77%；1100 → 7.43%；1200 → 35.5%；
   1500 → **91.4%**；1732.05 → **100%**。⇒ `d = 1000` **余量恰为 0**。

### 4.4 缺口清单（按优先级）

| # | 缺口 | 为什么重要 |
|---|---|---|
| 1 | **端到端跑通一次** | 没有它，全部性能数字都只能标"实测待填" |
| 2 | **`sector_probe` 接线进主控** | 它是"单观测频道"的唯一兜底；不接线则理论上 100% 清除在实现层有缺口 |
| 3 | 半平面内点数的实测分布 | Q4 定位层倾向小 `d`（更多格点落在同一扇区 ⇒ 更多示向度） |
| 4 | 三路清除在 Q4 的次数分布 | Q3 实测 direct 占 ~89%，Q4 待测 |
| 5 | `Q3 ⊆ Q4` 退化自检纳入回归 | 令全部 `u` 取空 ⇒ 应退化为 Q3；**免费的正确性证据** |

### 4.5 建议的推进顺序

1. **先跑一次 Q4 端到端**（演练，不限次数）：`一键_跑Q3.bat` 把 `'Q3'` 换成 `'Q4'`，或命令行
   `main_Q3Q4('Q4','<队号>')`。**Q3 已跑 63 局 ⇒ 首次演练是安全的**，重点看：
   `[网格] Q4 外扩环带：31 个检测点` 与 `[Q4] 全域 surrounding 自检` 是否通过。
2. 接上 `sector_probe`（**改主控，属真改动**）⇒ 补回归。
3. 建 `Q3 ⊆ Q4` 退化回归（构造全向源用例，断言输出与 Q3 一致）。
4. 再谈配图与性能数字回填。

⚠️ **不要把 Q3 的 63 局实测数据挪到 Q4 名下** —— 评委交叉比对即抓。

## 五、红线与陷阱

### 5.1 赛题红线（违反则整题不计分）

| 红线 | 出处 |
|---|---|
| 同一 `request_id` 只能在重试**完全相同**的动作时复用 | 附件2 §5.3 |
| **不得并发**发送不同动作 | 附件2 §1.4 / §12 |
| 必须**同时**检查 HTTP 状态码与 `accepted` | 附件2 §5.3 |
| `accepted=false` 时的 `virtual_time_s=0` **不是**当前虚拟时刻 | 附件2 §4.1 |
| 只有 `measure_result="direction"` 才读 `svd_deg` | 附件2 §7.2 / §12 |
| `/clear` 不切换频道 | 附件2 §1.3 |
| `no_signal` **不等于**附近无源 | 附件2 §2.2 |
| 测试结束后**不要**调 `/exit` 查原因 | 附件2 §9.3 |
| **不看模拟器内部数据**（读它的案例文件 = 绕过题设信息获取方式，且加密日志会自动上传，一眼可见） | 附件1 §4.6 |

### 5.2 本项目踩过的坑（**都已修，别重犯**）

| # | 坑 | 教训 |
|---|---|---|
| a | `pdist` 缺失 ⇒ 首局真机直接中止 | 新用函数前先 `exist` 一次；**不要假设工具箱齐全** |
