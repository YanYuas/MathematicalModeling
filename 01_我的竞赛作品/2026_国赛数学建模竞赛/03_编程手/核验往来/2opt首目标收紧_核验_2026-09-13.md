## 二、为什么这不成立 —— 4 条实测

### (1) 收紧邻域在数学上只能变差

2-opt 是**局部搜索**：邻域越小，可达解集越小。`i=1` 允许"反转前缀"（等价于换首点），
`i≥2` 不允许 ⇒ **A ⊇ B 的邻域** ⇒ `len(A) ≤ len(B)` 恒成立。

### (2) 本仓库的用法只消费 `ord(1)` —— 这才是关键

`main_Q3Q4.m` 阶段 A/B 的调用是：

```matlab
ord = optimize_route(tasks, cur_pos);   % tasks = 剩余格点 ∪ 待清源
task_kind = kind_of{ord(1)};            % ← 只取第一站
task_pick = idx_of(ord(1));             % 整条巡游随即丢弃，下一步重算
```

⇒ **只有 `ord(1)` 被消费**。而 `i≥2` 时 index 1 永不参与任何反转
⇒ `ord(1)` **恒等于**纯贪心最近邻的首站。

**实测钉死**（`cmp_twoopt_out.txt` §0）：

| 对照 | 25 步中 `ord(1)` 不同的步数 |
|---|---|
| B（`i=2:m-1`） vs **不做 2-opt** | **0** ⇒ B ≡ 纯 NN |
| A（`i=1:m-1`） vs 不做 2-opt | 1 ⇒ 2-opt 确实在改"下一站" |

⇒ **B 的 2-opt 对"下一站"是死代码**，白算一遍。

### (3) 代价可量化：网格巡游 +3464 m = **+693 s**

`cmp_twoopt_out.txt` §2（13 个 d=1000 格点，原点出发，递推取首站）：

| 版本 | 总行程 | 虚拟时间 |
|---|---|---|
| A（现状） | **12000 m** | **2400.0 s** |
| B（提案） | **15464 m** | **3092.8 s** |

`15464 m` **正是** `optimize_route.m` 头部注释记录的 2026-09-12 **真机实测**贪心值
—— 也就是说，B 把 2026-09-12 修掉的那个坑**原样恢复**（移动占虚拟时间 72~79%，是最大瓶颈）。

### (4) 带发现动态的随机重放：A 在 105/120 局更省，均值省 300 s/局

`cmp_twoopt_out.txt` §3（120 局；k~U[10,16] 均匀落圆域；**就近发现**：任一未清源距当前格点

## 四、给 Python 线的建议

1. **不要把 MATLAB 往 Python 收**，而是**把 Python 往 MATLAB 放**：
   Python 的 `range(1, len(order)-1)` 应改为 `range(0, len(order))`
   （即 `i` 从 **0** 起、`j` 到 `n-1`）。
2. 若 Python 侧"首目标必须固定"是**真实语义约束**（不是照抄来的限制），
   **请说明具体场景** —— MATLAB 线这边 `cur_pos` 就是侦察阶段的实际结束位置，
   它已经是巡游的起点（`optimize_route(points, start_point)` 的 `sp`），
   **不存在"首目标由侦察结束位置决定"** 这回事；`ord(1)` 是自由变量。
3. 双线并行**不以路由结果逐点相同为目标**（Python/MATLAB 各自求最优）；
   若为交叉验证需要可比的中间量，请约定**比较 `ord(1)` 之外的不变量**（如任务表、频道状态）。
