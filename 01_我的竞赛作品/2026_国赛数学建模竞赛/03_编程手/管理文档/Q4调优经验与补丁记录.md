## 一、致命缺陷（会导致"看起来正常但结果是错的"）

### I-1 【致命】`check_surrounding_all` 的采样行维度错 ⇒ Q4 一跑就崩

**现象**：`main_Q3Q4('Q4', ...)` 在生成网格后立刻抛
`对于此运算，数组的大小不兼容`，位置 `Q4_extensions.is_surrounding` 第 101 行。
⇒ **Q4 端到端从未跑通过**（与 V2.0 工作说明 §4.3 缺口 #1 "端到端零次" 完全吻合）。

**根因**：采样构造写成
```matlab
for th = linspace(0, 2*pi, nth+1); th(end) = []; Gs = [Gs; r*cos(th), r*sin(th)]; end
```
`th` 是**行向量** ⇒ `[r*cos(th), r*sin(th)]` 是 1×(2·nth) 列，而行本应恰好 2 列。
（顺带：`for th = <行向量>` 只迭代**一次**，所以不是逐方向循环，而是整行一次性拼接。）

**修复**：新增 `Q4_extensions.sample_disk(R, step, dense_boundary)` 统一构造（列向量拼接 +
边界带加密），`check_surrounding_all` 改为调用它。

**判据**：`run_assertions('Q4')` 断言 1 打印 "采样 20517 点 … 失败 0 (全域 0.00%，边界带 0.00%)"。

### I-2 【致命】`is_surrounding` 在 d=1000 上的浮点假性失败

**现象**：修好 I-1 后，全域自检报 **3/20517 失败**，首例 `G=(500.0, 866.0)`、`‖G‖=1000.0`
——恰好是格点。

**根因**：`d = 1000` 时，格点顶点的**第三近邻距离恰为 d = R_eff = 1000**（余量 0）。
`sum((P-G).^2,2) <= R_eff^2` 的严格比较把 `1000.0000000000002` 判成"超出"。
物理上"距离 = R_eff"是**可测**的（附件2 §2.1「不超过有效接收半径」）⇒ 必须含边界。

**修复**：`Q(P) = {‖p−G‖ ≤ R_eff + 1e-9}`（与 W4 的扇区判定同一套容差口径）。

**判据**：全域失败 3 → **0**；且 `stats.third_nearest_max` 打印为 1000.00 m、`margin` 0.00 m。
**这是"余量恰为 0"从纸面警告变成可观测指标**的地方 —— 建模手建议 `d ≤ 950`，
本次仍按 v2.0 基线的 `d = 1000` 跑（与全部既有文档口径一致），但余量指标现在会打印出来。

### I-3 【致命】`handle_no_signal_Q4` 是**静默死代码**，扇区探针实际从不触发

**现象**：`main_Q3Q4.m` 的 Q4 分支调 `handle_no_signal_Q4(pos, ch, ...)`，
而该函数把**检测点本身**当作"干扰源估计位置 G"，再判 `is_surrounding(G)`。
检测点正是格点 ⇒ 恒被判为"被 surrounding" ⇒ 函数恒返回 `skip` ⇒ **探针分支永不执行**。
（论文组织方案 §2.4 已指出"探针未接入主控"，这里进一步查明：**即使按旧接线也不会触发**。）

**修复**：删除该函数与其调用。`no_signal` 分支只做语义注释：Q4 的三义 ⇒ 判空只能靠全 `P` 遍历
（`ChannelStateMachine` 已按 `position_id` 去重计数，W12）。

**判据**：删除后 `run_assertions('Q4')` 全绿；探针改由 §二 P-1 的**正确接口**接入。

## 二、补丁（功能补全）

### P-1 `sector_probe` 重写并**真正接入主控**

**旧实现的问题**：三点判别法（相位 120°、`r_probe=50`），**与引理 Q4-D 无关**：
不是垂直视线偏移，会把探针点送到 `R_eff` 之外，也不回传观测。

**新实现**（`Q4_extensions.sector_probe(obs_pos, svd_deg, channel, sim_client, config)`）：
- `n̂ ⊥ (p−G)`：已知 p 处示向度 θ（p→G 的方位角）⇒ 取 `θ+90°`；
- `q_± = p ± b·n̂`，**先 q₊ 后 q₋**，固定两次（W11，不写成循环重试）；
- `b = config.sector_probe_step`（默认 100 m）；两轮都 `no_signal` 时按 G5 减半到 25 m 再试一轮，
  **共 ≤2 轮 4 次**，仍失败则放弃并打印原因；
- 命中 `direction` ⇒ 回传观测（位置 + `svd_deg`）；命中 `near` ⇒ 回传"可直接清除"。

**接入点**：阶段 A 扫描结束后（`main_Q3Q4.m` §5.5）。只对
**`is_cleared=0 ∧ is_confirmed_empty=0 ∧ 观测数恰为 1`** 的频道补测 —— 这样探针只在真正需要时触发
（Q4 的 `d=1000` 下多数定向源天然拿到 ≥2 条示向度，实测 3 局只在 seed=7 触发 1 次）。
补测按 `optimize_route` 就近排序（探针是局部动作，不打乱主巡游，W22）。

**判据**：`test_sector_probe(port)`（新增）用 `_mock_simulator.py --mode sector` 构造两个用例：
① `q₊` 落在盲区、`q₋` 命中（探测 2 次）②`q₊` 直接命中（探测 1 次）；
两例都断言返回点在扇区内、示向度指向真实源、距源不超过 `R_eff`。

### P-2 扫掠清除改为**覆盖整个 L**（W6），并加覆盖自检

**旧实现**：沿示向度"定向短走"一个清除半径再试。
**为什么 Q4 必须换**：定向源**盲侧永不返回 `near`**（附录2(9)），短走依赖的示向度会在滑出扇区时中断
（陷阱 W8）；而 `/clear` 的成功条件只看距离（附录2(8)）⇒ **覆盖 L 的扫掠对朝向完全免疫**。

**新实现**：`sweep_centers(L, dil)`（**独立函数文件**，便于断言直接测生产同一份逻辑）
- 三角格间距 `s = dil·√3` ⇒ 外接半径恰为 `dil`；保留 `dist(p,L) ≤ dil` 的格点（含内部）；
- 补 L 的**顶点与边中点**（W6：要盖住角）；
- **覆盖自检 + 贪心补点**：沿边界按 2 m 采样，有缝就把该点补成中心（2 轮）。
  这一层是给"L 非凸"留的保险：生产 L 恒凸，但实现不应依赖该前提。

**判据**：`run_assertions('Q4')` 断言 7 —— 40 个随机 L（每 8 个夹一个**非凸**用例，
内部 200 点 + 边界 2 m 采样）实测**最大空隙 19.73 m ≤ 20**；
`test_sweep_clear` 断言"扫掠全程 `/measure` 次数 = 0"（确实不读示向度）。

### P-3 定向源 homing 断线 ⇒ **扫掠兜底**（离线实测抓到的真缺陷）

**现象**：8 种子批跑里 **seed=7 只有 92.3%（12/13）**，频道 3 未清除。

**根因链**（离线日志逐行还原）：频道 3 的交会结果 `R_MEC = 142.91 m` > 84.0369 ⇒ 走 homing；
homing 走到第 2 步返回 `no_signal` ⇒ 示向度中断 ⇒ 停止逼近 ⇒ **未清除**。
这正是 Q4 全解总览 §5.2 预言的"定向源一旦在逼近中滑出扇区，示向度就断"。

**修复**（两层）：
1. `clear_source.m` 的 homing 分支：失败后若 `L` 可用且 `R_MEC ≤ config.R_sweep_fallback_max`
   （默认 250 m）⇒ 转 `sweep_clear_L`，`mode` 记为 `homing_fallback`（单列计数，不混入 homing）；
2. `main_Q3Q4.m` 阶段 C：频道有 ≥2 条观测时**先交会**再按三路清除（原来无条件走单方位 homing，
   把"有 L 却不用"的路径堵死了）。

**判据**：同一批种子重跑 ⇒ seed=7 变 **100%**（`homing 0`、`homing_fallback` 计入 sweep）。

## 三、工装/平台缺陷（不修就会拿到**假数字**）

### T-1 【最贵】迷你模拟器用 HTTP/1.0 ⇒ MATLAB 每次请求 1.1 s，离线计时被高估 ~100×

**现象**：Q4 离线一局"程序墙钟"**336 s**（Q3 记忆里是 ~3 s，矛盾）。

**定位**（`bench_http.m`，一次会话量三块）：

| 环节 | HTTP/1.0 | HTTP/1.1（长连接） |
|---|---|---|
| 完整 client（webwrite + JSONL 落盘） | **1127.09 ms/次** | **11.19 ms/次** |
| 裸 `webwrite`（不落盘） | **1122.71 ms/次** | **6.52 ms/次** |
| 仅落盘 | 6.58 ms/次 | 7.07 ms/次 |

Python 客户端对同一服务只要 **9.72 ms/次** ⇒ **瓶颈全在 MATLAB 侧的重连**，不是服务器。

**根因**：`BaseHTTPRequestHandler` 默认 `protocol_version = "HTTP/1.0"` ⇒ 每次响应后关连接 ⇒
MATLAB 的 Java HTTP 客户端每次重连 + 重解析，约 1.1 s。

**修复**：`_mini_sim_q4.py` **与** `_mini_sim_q3.py` 都显式设 `protocol_version = "HTTP/1.1"`。

**影响面**：只影响**墙钟**；虚拟时间（`virtual_time_s`）不受影响，故 Q3 既有的虚拟时间口径数字不变。
**但"程序墙钟"类的离线数字必须重跑**。

### T-2 MATLAB 函数文件名不能以 `_` 开头

`_bench_http.m` 直接报"文本字符无效 / MATLAB 文件名无效"。改名 `bench_http.m` 即好。
（`核验脚本/` 下的 `_*.py` 是 Python，不受此限。）

### T-3 离线驱动的两个小坑

1. MATLAB 变量名 `r0`、`r{i}` 都不是合法用法 —— `r0` 合法但 `r{0}` 不是；改成 `r1..rN` + `eval(sprintf('r%d',i))`。
2. `fprintf` 的**格式串说明符个数**少于参数个数时 MATLAB **循环重排格式**，
   会多打印一行并把解析错位（表现是 `KeyError`）—— 加参数必须同时加 `%d`。

### T-4 测试取样器不能用"质心射线法"

`sample_poly` 旧版按质心射线求 `rmax` 再取样，实测 **200 点里有 27~49 个落在多边形外** ⇒
断言 7 假性报"最大空隙 113 m"。改用**拒绝采样**（包围盒撒点 + `inpolygon` 过滤），凸凹通吃。

### T-5 并发跑离线驱动会互相踩（复现了记忆里的坑）

本机 2026-09-13 实测：第一次驱动被中断后**遗留一个 MATLAB 进程**仍在跑，
第二个驱动按固定端口 `kill_port` 起新模拟器 ⇒ 遗留 MATLAB 连到了**别人的案例**上。
修法：`_run_mini_sim_q4.py` 的 `BASE_PORT = 20300 + (os.getpid() % 400)`，
按 PID 错开端口，不再抢固定端口。

## 四点五、后续补丁（4.2 暴露的两个残留缺陷）

### P-4 `R_sweep_fallback_max` 从 250 m 提到 1000 m（8 种子批跑暴露）

**现象**：P-3 的兜底加好后，3 种子全过；**8 种子**里 seed=11/42 仍各掉 1 个源（92.3%）。
日志显示：频道 19 交会得 `R_MEC = 304.31 m` ⇒ 走 homing ⇒ **第 1 步就 `no_signal`**
⇒ 走兜底时被 `R_MEC ≤ 250` 挡下 ⇒ 未清除。

**根因**：250 这个上限是我拍的，没算过实际分布。`R_MEC` 在 Q4 里因交会几何劣化
（半平面内格点少 ⇒ 两观测夹角小）可以轻松到 300 m 量级。

**修复**：上限提到 **1000 m**（覆盖全部实际可能；`L ⊆ D` ⇒ `R_MEC ≤ 1800`），
真正的成本闸门换成**虚拟时间预算** `config.sweep_budget_s = 6000 s`
（在 `sweep_clear_L` 的循环里按 `sim_client.virtual_time` 增量判，超了收手）。
配合原有的"中心数上限"与"现实时间预留"两道保险。

**判据**：8 种子重跑 ⇒ **8/8 全部 100%**，`homing` 归零、兜底 7 次生效；
最坏一局 `seed=11` 多花 150 次 `/clear` + 约 1700 s 虚拟时间，墙钟 13.8 s（远在 1200 s 内）。

### P-5 导出机器可读的本局汇总 + 汇总表脚本

  n_probe_* / R_MEC_* / surrounding_* / is_replay / sim_url` —— 这是"导出数据供再调试"的落点。

## 八、离线工具的局限（2026-09-13 总控转交，实测）

### 8.1 离线迷你模拟器覆盖不到阶段 A 的长任务表

离线批跑固定 **n = 13 源**；真机的 `k` 实测在 **10~16** 浮动，且真机会出现同频道多源、
判空频道多、待清队列长的情形。阶段 A 的主循环长度与「剩余格点 ∪ 待清源」的表长
因此**显著变长**。

P-12（一次规划整条任务序列、连走 K 步再重规划）正是栽在"表长 × 连走 K 步"的边界上：
**离线 16 种子受控对照通过，真机跑到阶段 A 卡住**（16:26:51 那局只走到 `/enter`，
2 行日志）。回退后 16:27:38 立刻跑通。

**规矩**：凡改动**阶段 A 的调度结构**（任务表的构成、重规划频率、首站选择），
**必须真机验一局**，不能只凭离线对照。离线的结论只作方向性证据。

### 8.2 控制台输出被下游脚本当接口

`核验脚本*/` 与 `核验脚本_Q4/` 里的驱动会解析 MATLAB 打给人看的字符串。
本项目已发生三次措辞改动，其中一次（改 `/enter` 重试提示的措辞）让
`_test_enter_wait.py` 的断言**静默失效**（正则匹配不到 ⇒ `bool(...)` 恒为假，不报错）。

**规矩**：**凡改 `fprintf` / `warning` / `error` 的字符串措辞，先 grep 一遍
`核验脚本*/` 与 `核验脚本_Q4/`。**

2026-09-13 自查结论（本次代码精简之后）：全仓含中文的解析模式**只有两条**
（`_test_enter_wait.py` 的 `等待接口开放` 与 `/enter 等待 [\d.]+ s 后成功`），
两条都已核对**仍然有效**；其余驱动一律走 ASCII 标记
（`Q4ROW` / `Q4SELFTEST_SUMMARY` / `SELFTEST_SUMMARY` / `MINI_DONE`），措辞可自由改。

### 8.3 引用分布/比值做论断前的自查（与总控 §2.3 同构）

「事后重排同一批点只需实走的 70~89%」衡量的是**静态**最优，动态策略抓不到 ——
我拿它论证"阶段 A 可重构"是错的推论。同构错误在论文侧也有（把 `R_MEC` 的
**最坏配对分布**当成**运行分布**引用）。

**规矩**：引用一个分布或比值做论断前，先问 —— **这个量是在什么条件下测的？
与我要论证的场景同条件吗？**
