## 二、时间窗（最容易翻车的地方）

```
确认开始测试
   ↓
模拟器准备案例数据 → 显示 5 秒倒计时 → 倒计时结束：开启 25 分钟窗口 + 开放机器狗接口
   ↓
程序调用 /enter 成功 → 开始算「程序运行时间」，最长 20 分钟
   ↓
实际截止 = min(25 分钟窗口截止, /enter 成功后 20 分钟)   ← 附件2 §4.5
```

**两条硬约束**：
1. ⚠️ **MATLAB 启动约 40 秒**。必须在**倒计时结束前**就把 `一键_跑Q3.bat` 启动起来并输完队号，
   否则 GUI 里 5 秒倒计时一过，你的程序才开始启动，`/enter` 会晚于窗口开始 **5 分钟**红线之后
   ⇒ 实际可用时间不足 20 分钟（程序会打印提示）。
2. `/enter` 响应里的 `remaining_real_duration_s` 是**本局真实可用秒数**（0–1200），
   程序已按它控制收尾（`config.time_reserve = 60 s`），**不要**假定每次都是 1200。

**截止**：北京时间 **2026-09-13 17:30** 后不能启动新测试；**建议 09-13 15:30 前**完成全部三次正式测试（附件1 §4.2）。

## 三、跑一次（演练 / 正式都一样）

### 3.1 操作顺序

1. 启动模拟器 → **联网登录**（需要验证码/密码）→ 选模块（问题 3 演练 / 问题 3 正式）
2. **先双击 `一键_跑Q3.bat`**，按提示输入：
   - `robot_id` = **你的参赛队号**（必须与模拟器当前登录队号逐字节一致）
   - 测试案例编码（可选。**正式测试结束后**从模拟器界面抄回来也行 —— 见 §四）
3. 回到模拟器，**确认开始测试**
4. 等 5 秒倒计时结束 → 程序会自动 `/enter`（它在等接口开放；早调用会连不上，程序**会自动重试**）
5. 程序跑完自动 `/exit`，打印表 1 四列 + 日志路径

> 若程序比倒计时先就绪：正常。接口未开放时连接被拒，程序按附件2 §12 用**原 request_id 重试**，
> 直到接口开放 —— 这正是赛题要求的行为。

### 3.2 命令行等价做法（不想用 bat 时）

```bat
"D:\R2026a_Windows\bin\matlab.exe" -nosplash -sd "<本目录>" -batch "main_Q3Q4('Q3','<参赛队号>')"
```
Q4 同理，把 `'Q3'` 换成 `'Q4'`。

## 五、日志（本程序写的那份）

- 位置：`MATLAB_Framework/logs/robot_<队号>_<时间戳>.jsonl`（**由本文件位置推导，不看当前目录**）
- 每行一条 JSON，覆盖**每一次**请求（含失败的尝试）：
  `seq / kind / wall_clock_ms / elapsed_wall_s / endpoint / attempt / request_id /
   request_payload / response_payload / http_status / response_received / accepted /
   virtual_time_s / transport_error / error_identifier`
- 另有 `session_start` / `session_end` 两条记录（`session_end` 含程序运行时间）
- 满足附件1 §4.6 与附件2 §12「机器狗程序应自行记录测试过程中的指令序列、响应信息等内容」

## 七、改代码时的红线

| 红线 | 出处 |
|---|---|
| 同一 `request_id` **只能**在重试**完全相同**的动作时复用；改内容即 HTTP 409 | 附件2 §5.3 |
| **不得并发**发送不同动作（须逐次等完整响应） | 附件2 §1.4 / §12 |
| 必须**同时**检查 HTTP 状态码与 `accepted`，不能只判一个 | 附件2 §5.3 |
| `accepted=false` 时 `virtual_time_s=0` **不是**当前虚拟时刻 | 附件2 §4.1 |
| 只有 `measure_result="direction"` 才读 `svd_deg`，且它**含 ±1° 误差** | 附件2 §12 |
| `/clear` **不切换**测向机频道，也不产生切换耗时 | 附件2 §1.3 |
| `no_signal` **不等于**附近没有源（可能超接收距离 / 定向盲区） | 附件2 §2.2 |
| 测试结束后**不要**调 `/exit` 查原因（接口已关） | 附件2 §9.3 |

## 九、2026-09-12 首次真实演练复盘（**已修，但值得知道**）

**现象**：真实跑了一次，程序在阶段 A 扫完之后**就停了** —— 机器人日志里 `/measure` 之后
**再无任何记录、也没有 `/exit`**，终端显示报错。

**日志证据**（`logs/robot_*.jsonl`）：`/enter` 1 条 + `/measure` **261** 条 + `/clear` **0** 条
+ `/exit` **0** 条，**无 `session_end`**；262 条请求全部 `accepted=true`、零重试
⇒ **传输层是好的，是 MATLAB 侧代码崩了**。

**定位过程**：阶段 A 是 13 格点 × 20 频道 = 260 次 measure（`seq 3..262`）；
`seq=263` 的位置 `(-1437.1, 188.2)` 不在格点上 ⇒ 那是**阶段 B 的 `homing_clear` 起点** `mean(L)`
⇒ 崩在 `homing_clear` 里、且在**第二次 measure 之前**。

**两处根因**：

| # | 缺陷 | 后果 |
|---|---|---|
| **1（主因）** | `D = max(pdist(L))` —— **`pdist` 属 Statistics Toolbox，本机未安装**（实测 `exist('pdist','file')==0`） | 未定义函数 ⇒ **程序中止**。已改用项目自有的 `Q1_geometry.polygon_diameter`（暴力最大两两距离，语义相同，**已被断言 4 验证**，无工具箱依赖） |
| **2（潜在）** | `theta_old = result.svd_deg` 无条件取值 —— 但附件2 §7.2 规定 `svd_deg` **只在 `measure_result=="direction"` 时返回** | `no_signal`/`near` 时报"无法识别的字段名" ⇒ 同样中止。已新增 `svd_of()` 守卫：拿不到示向度就**如实放弃**并记日志，不崩 |

**同类排查**：已对整个 `MATLAB_Framework/` 做**全量标识符扫描**（抽出所有函数调用式标识符、
排除变量与本地函数，逐个 `exist` 测试）⇒ **除 `pdist` 外无其它缺失函数**（`posixtime` 是误报，
日志证明它可用）。⇒ "未定义函数"这一类已关闭。

**新增回归测试**（免模拟器、免联网）：`核验脚本\一键_跑MATLAB离线自测.bat` 现覆盖 **11 项**：
5 项客户端合规自测（`ok`/`accepted_false`/`http400`/`http409`/`hang`）+ **2 项 `clear_source` 回归**
（`homing` 走完全程；`no_signal` 安全放弃）+ `homing` 收敛 + `sweep_clear` 定向短走 +
阶段 C 单方位 homing + 路径优化。**全过才退 0**（2026-09-13 实测 11/11）。

⚠️ **仍未验证的部分**：**Q4** 未过端到端实跑（Q3 已跑 23 局，见下）。

✅ **Q3 已实跑验证**（2026-09-12 十三局 + 2026-09-13 十局）：**23/23 局 100% 清除**，

## 十、⚗️ d=1500 试跑结论：**不可用，已回退 1000**（2026-09-12）

**试跑实测**（12 源案例）：

| 项 | d=1000 | **d=1500** |
|---|---|---|
| 虚拟时间 | 7343.9 s | **26242.5 s** |
| 移动占比 | 78.0% | **93.5%** |
| 清除成功 | 12 | **7** |
| 均摊 | 612 s/源 | **3748.9 s/源** |

⇒ 格点变稀使定位不确定度变大 ⇒ 大量落入 `homing` 分支，而 **homing 当时是不收敛的**
（原地 4 点循环、每频道烧 ~1050 s 且清不掉）⇒ 整局被拖垮。**`config.grid_spacing` 已改回 1000。**

**但 `homing` 本身已修好**（这才是关键）：权威数字表记 **32.7% 的可解区需要 homing**
⇒ 即使 d=1000，正式测试也可能抽到需要 homing 的案例 —— 旧实现照样会炸。

修复方案：只前进不后退、步长上限 300 m、**过冲时步长减半（几何衰减 ⇒ 必然收敛）**、
移动/迭代双上限保护 20 分钟预算。**实测**：起点距真源 800 m ⇒ **9 次检测、1069 m、
收敛到距真源 1.6 m、清除成功**（回归测试 `test_homing_convergence.m`，9 项自测之一）。

**下一步建议**：用 d=1000 重跑一次演练，确认 ⑴ 清除比例仍 **100%**（看模拟器结束界面的
「本局干扰源总数」）⑵ 均摊时间回到 **479 s 量级**（路线优化 −21% + homing 修复）。

> ⚠️ **不要用离线 mock 评估时间**：mock 只按"每次检测 +5 s"累加虚拟时间，**不含移动与频道切换耗时**
> ⇒ 它能验协议行为与崩溃/收敛回归，**不能**验策略耗时。时间只能从真模拟器量。
