## 一、要砍的是什么

25 局径向档真机日志的时间账分解：

| 分量 | 占比 |
|---|---|
| 移动 | 71.8% |
| 检测 | 22.0% |
| 切换 | 4.2% |
| 清除 | 2.0% |

移动/切换/判空三项都已在下界附近，唯一可砍的是**检测**里的这一段：

> 某频道在格点 A 被听到 **1 次**（拿到示向度）之后、拿到第 **2 次**之前的重复测量。

因为交会定位（`triangulate_source`）**只用前两条观测**，所以这中间每一次测量**只有当它给出第 2 个观测时才有价值**；否则纯白付 5 s 检测 + 1 s 切换。

实测（径向档 25 局）：这类空测 **15.6 次/局**，另有"已有 2 观测后"0.9 次/局 ⇒ 上限约 **99 s/局 ≈ 7.7 s/源 ≈ 2.5%**。

## 二、判据（声线过滤）

已知源在 A 被听到，示向度 θ（附件2 §7.2），故：

```
源 ∈ 射线{ A + t·u(θ), t ≥ 0 }  且落在半径 R_domain 的圆域内
```

在格点 p 处**可能**拿到第 2 个观测 ⟺ 存在这样的源使 `dist(p, 源) ≤ R_sensor`。

判据（保守）：

```
u = (cos θ, sin θ)
L = 2·R_domain                       ← 域内任意两点距离上界
d = dist(p, 线段[A, A + L·u])
spread = L · sin(epsilon_deg)        ← 示向度 ±1° 造成的横偏上界
放行  ⟺  d ≤ R_sensor + spread
```

### 为什么保守（不会丢观测）

设真源 s 满足 `dist(p,s) ≤ R_sensor`。s 在偏角 δ（|δ| ≤ ε）的射线上、距 A 为 t ≤ L：

* s 到轴线 u 的垂距 = `t·|sin δ| ≤ L·sin ε` = spread，且其投影 t·cos δ ≤ t ≤ L 落在**线段内**
  ⇒ `dist(s, 线段) ≤ spread`
* 又 `dist(p, 线段) ≤ dist(p, s) + dist(s, 线段) ≤ dist(p,s) + spread ≤ R_sensor + spread`
  ⇒ 判据**放行**。∎

即：**只要 p 真能看到源，过滤就不会拦它。**

### 依赖的假设

源位于半径 `R_domain` 的圆域内。策略的覆盖设计（径向 13 点、覆盖自检）本就默认这条。

## 三、被证伪的"加强版"（记录在案，别再试）

直觉上把 `L` 收紧成"射线到圆域出口的长度"会拦得更狠，且看起来更聪明。**实测不成立。**

`test_ray_filter.m`（6000 例，A/p/源都按真机条件落在域内）结果：

| 变体 | `L` 取值 | 放行率 | 违例 |
|---|---|---|---|
| **变体1** | `2·R_domain` = 3600 m | 41.8% | **0** ✅ |
| 变体2 | 射线到圆域出口 | 40.0% | **1 / 6000** ❌ |

**根因**：出口长度**随偏角变化** `L(δ)`。用中心射线的 `L(0)` 去界定偏角射线上源的位置，
当 A 靠近域边界、θ 近切向时 `L(±ε)` 可比 `L(0)` 大得多，源就落到了判据的锥体之外。
—— 收益只有 1.8 个百分点，代价是一颗**静默缺陷**：那条通道拿不到第 2 个观测，
堕入阶段 C 单方位 homing，甚至清不掉。**与 P-7 是同一类失效。**

⇒ **采用变体1。**

### 为什么另写 `ab_driver.py` 而不用仓库的 `_run_mini_sim.py`

2026-09-13 实测踩到的三个问题（**仓库脚本未改**，另写一份）：

1. 它把迷你模拟器的 `stdout` 接到 `PIPE` 却**从不读取** ⇒ 管道写满即死锁（本实验实际卡死过一次）；
2. 每个种子复用**同一个固定端口** 20290 ⇒ 与其它窗口/残留实例互相踩（I-5a 的并发变体）；
3. 卡住时只表现为"这个种子特别慢"，**不报错**。

`ab_driver.py` 的对策：每局独占端口、子进程输出落文件、端口先确认空闲、
MATLAB 超时保护、失败重试一次、结果落 JSON。

### 6.2 正确性

| 检验 | 规模 | 结果 |
|---|---|---|

### 6.3 收益的量级（说清楚，别高估）

−1.3%，即 **4.1 s/源**。对照两件事读：

* 上限是 **2.5%**（检测+切换里唯一可砍的那一段），实测拿到它的约 6 成；
* 真机上 `均摊` 的**主要摆幅来自抽到几个源**（n=11 → 355 s/源，n=16 → 215 s/源，
  差 65%）—— 1.3% 不改变任何结论，只是把同样的曲线整体压低一点点。

**结论**：改动小、证据强、收益小。是否上到交付树，见 §七。

### 7.2 两处收益的稳定性**不一样**（别混着报）

| 种子组 | 基线虚拟 | 合成虚拟 | Δ | 均摊 |

* **声线过滤**：两组都为正（−1.3% / −2.0%）。它省的是纯浪费（源不可能在范围内的格点），
  逻辑上**不可能为负**。
* **Or-opt**：第一组 −1.9%，第二组 **0**（移动 13987/13934 逐位未变）。是"有时赢" ——
  2-opt 恰好已到 Or-opt 最优时就没有收益。**它也可能让总移动微增**（seed 11：13985 → 13987），
  因为每步只消费 `ord(1)`，更好的整条路线会导出不同的第一步。
