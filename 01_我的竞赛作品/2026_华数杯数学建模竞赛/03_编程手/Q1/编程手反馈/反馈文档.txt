核心函数:


def get_adaptive_sa_params(initial_gap, base_params):
    """根据初始解gap动态调整SA参数"""
    params = base_params.copy()
    
    if initial_gap < 10:
        # FFD类：gap<10%，保守参数
        params['L_factor'] = 50          # 10 → 50（5倍迭代）
        params['max_no_improve'] = 20    # 8 → 20（更多容忍）
        params['T_final'] = 0.01         # 0.1 → 0.01（允许更低温度）
        params['k'] = 7                  # 5 → 7（恢复原始快冷阶段）
        tier = "CONSERVATIVE (FFD-like)"
        
    elif initial_gap < 100:
        # greedy_random类：gap 10-100%，标准参数
        tier = "STANDARD (Ultra-fast)"
        
    else:
        # random类：gap>100%，激进参数
        params['L_factor'] = 5           # 10 → 5
        params['max_no_improve'] = 3     # 8 → 3
        params['T_final'] = 1.0          # 0.1 → 1.0
        tier = "AGGRESSIVE (random-like)"
    
    return params, tier

💡 关键经验总结
1. 分层参数设计原则
问题: 单一参数集无法适应不同质量的初始解

解决: 根据初始gap动态调整

好初始解（gap<10%）→ 保守参数（允许精细搜索）
中等初始解（gap 10-100%）→ 标准参数
差初始解（gap>100%）→ 激进参数（快速下降）
适用场景: SA/遗传算法等元启发式的初始化优化

2. 时间计算的学术标准
发现: time字段应统一为"总时间"（构造+优化）

依据: SA论文标准（MCNC/GSRC benchmarks）报告完整算法的wall-clock time，不是子模块增量

教训: greedy的time=0会严重误导读者

3. 数据验证优先于优化
教训:

报告声称"超时问题"但数据显示平均102s<120s
应先验证问题存在，再投入优化资源
数据审计是修复的第一步
