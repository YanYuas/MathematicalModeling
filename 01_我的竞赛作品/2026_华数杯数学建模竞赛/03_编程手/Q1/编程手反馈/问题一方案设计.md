# B题问题一：基础布图规划 — 多方案设计与融合

## 问题描述

给定 $n$ 个**硬模块**（固定宽度 $w_i$、固定高度 $h_i$）和连接关系（网表 netlist），设计布图方案，实现：

- **主目标**：芯片总面积 $A_{total} = W \times H$ 最小
- **副目标**：芯片长宽比 $R = \max(W, H) / \min(W, H)$ 尽可能接近 1（即芯片形状接近正方形）

模块不可重叠。

**为什么要控制长宽比**：
- 芯片实际制造中，过于狭长的芯片（$R \gg 1$）会导致封装困难、散热不均
- 标准芯片封装要求 $R \leq 2$，理想值 $R \approx 1$
- 长宽比越接近 1，芯片可制造性越好

**核心难点**：
- 组合爆炸：$n$ 个模块排列数为 $n!$，30 个模块 ≈ $2.65 \times 10^{32}$ 种可能
- 拓扑表示：如何用紧凑数据结构表达模块间相对位置，同时保证无重叠
- 搜索效率：如何在指数级解空间中找到近似最优解
- 多目标权衡：面积和长宽比往往冲突——面积最优布局可能非常狭长

---

## 多目标处理策略

问题一是**主次分明的双目标优化问题**，采用**加权和法（Weighted Sum）**：

### 统一代价函数

所有方案共用以下代价函数：

$$
C(T) = A_{total} + \lambda \cdot (R - 1)^2
$$

其中：

| 符号 | 含义 | 计算方式 |
|------|------|---------|
| $A_{total}$ | 芯片总面积（**主目标**） | $A_{total} = W \times H = \max_i(x_i+w_i) \times \max_i(y_i+h_i)$ |
| $R$ | 芯片长宽比（**副目标**） | $R = \max(W, H) / \min(W, H) \geq 1$ |
| $\lambda$ | 长宽比惩罚系数 | $\lambda = 0.05 \cdot A_{\min}$，$A_{\min} = \sum_i w_i h_i$ |

### 为什么选加权和而不是其他方法

| 方法 | 适用场景 | 问题一是否适用 | 理由 |
|------|---------|:---:|------|
| **加权和（Weighted Sum）** ✓ | 目标有明确优先级 | ✅ | 面积是主目标，长宽比是软约束，加权和简单有效 |
| ε-约束法 | 一个目标必须满足硬约束 | ❌ | 长宽比没有硬性上限（题目未规定 $R \leq 2$） |
| NSGA-II | 目标同等重要，需 Pareto 前沿 | ❌ | 过度复杂，且主次关系明确 |
| Lexicographic（字典序） | 目标有严格优先级 | ⚠️ 可以考虑 | 但过于刚性——可能为了极微小的长宽比改善而接受面积大幅增加 |

### λ 取值的合理性

- **$\lambda = 0.05 \cdot A_{\min}$**：长宽比惩罚约为面积的 5%
- 假设两个解面积相同（$A_{total} = 1.2 \cdot A_{\min}$），一个 $R=1$（正方形），另一个 $R=1.5$：
  - $\Delta C = 0.05 \cdot A_{\min} \cdot (0.5^2) = 0.0125 \cdot A_{\min}$
  - 即面积差异需小于约 1% 时，长宽比才会改变选择
- **保证主目标优先级**：面积改善 2% 以上时，长宽比差异不会扭转决策

## 方案总览

从**拓扑表示**和**搜索算法**两个维度设计 4 套独立方案 + 1 套融合方案。

| 编号 | 方案名称 | 拓扑表示 | 搜索算法 | 论文定位 |
|------|---------|---------|---------|---------|
| 方案1 | B*-Tree + SA | B*-Tree（二叉树）| 模拟退火 | **主力方案** |
| 方案2 | SP + SA | Sequence Pair（双排列）| 模拟退火 | 表示完备性验证 |
| 方案3 | B*-Tree + GA | B*-Tree（二叉树）| 遗传算法 | 算法对比验证 |
| 方案4 | 贪心 + LS | B*-Tree（二叉树）| 贪心构造 + 爬山 | 确定性 baseline |
| **融合** | **Memetic 四阶段混合** | **B*-Tree + SP跳跃** | **GA内嵌SA + 完整SA** | **最终方案** |

```
方案1（B*-Tree+SA）        ← 主力，参考文献经典方法，收敛快
  ├── 方案2（SP+SA）       ← 同算法不同表示：验证 B*-Tree 的表示充分性
  ├── 方案3（B*-Tree+GA）  ← 同表示不同算法：验证 SA 的搜索充分性
  └── 方案4（贪心+LS）     ← 确定性 baseline：展示随机优化提升幅度
```

## 方案1：B*-Tree + 模拟退火（SA）— 主力方案

### 核心思路

用 B*-Tree 紧凑编码模块位置关系（O(n) 压缩），以**面积为主目标、长宽比为副目标**的加权代价函数，通过模拟退火的 Metropolis 接受准则在解空间探索，从高温渐进收敛到低温，逼近全局最优。这是 VLSI 布图规划中**效率与质量平衡最好**的经典方案，参考文献（Chang et al., DAC 2000）直接采用此方法。

### 拓扑表示：B*-Tree

**编码规则**：
- 有序二叉树，每个节点对应一个模块
- 根节点位于左下角 (0, 0)
- 左子节点置于父节点右侧紧邻（abut）
- 右子节点置于父节点上方（stack）
- 每棵 $n$ 节点的 B*-Tree 唯一对应一个无重叠 compact packing

**旋转处理**：每个节点附带旋转标志位 $r \in \{0, 1\}$，packing 时按标志调换 $(w_i, h_i)$。

**B*-Tree 到坐标的转换（Packing 算法）** $O(n)$：
1. 按 DFS 序访问节点，维护水平轮廓线（contour）——当前已放置模块的上边界分段
2. 左子节点：`x_child = x_parent + w_parent`，`y` 由轮廓线在 `x_child` 处的最低位置确定
3. 右子节点：`x_child = x_parent`，`y` 由轮廓线在 `x_child` 处的最低位置确定
4. 更新轮廓线，计算包围盒：$W = \max_i(x_i + w_i)$，$H = \max_i(y_i + h_i)$

```
PACK(T):
  contour = [(0, ∞, 0)]       // 初始轮廓线：(x_start, x_end, height)
  for node in DFS(T):
    if node is root:
      (x, y) = (0, 0)
    elif node is LEFT_CHILD(parent):
      x = parent.x + parent.w
      y = contour.lowest_at(x)
    elif node is RIGHT_CHILD(parent):
      x = parent.x
      y = contour.lowest_at(x, x + node.w)
    contour.update(x, x + node.w, y + node.h)
    W = max(W, x + node.w)
    H = max(H, y + node.h)
  R = max(W, H) / min(W, H)  // 长宽比
  return (W, H, R, all_coords)
```

### 目标函数

由于问题一是**双目标优化**（主目标面积最小 + 副目标长宽比趋近1），采用加权代价函数：

$$
C(T) = \underbrace{A_{total}}_{\text{主目标：面积}} + \lambda \cdot \underbrace{(R - 1)^2}_{\text{副目标：长宽比惩罚}}
$$

其中 $R = \max(W, H) / \min(W, H)$，$\lambda$ 为长宽比惩罚系数。

**权重设计说明**：
- $(R-1)^2$ 用平方惩罚：$R$ 偏离 1 越多惩罚增长越快
- 当 $R=1$（正方形）时，惩罚项为 0
- $\lambda$ 的选取要保证**主目标优先**：面积改善 1% 的代价应大于长宽比从 1.5 降到 1.4 带来的收益
- 推荐 $\lambda = 0.05 \cdot A_{\min}$（其中 $A_{\min} = \sum w_i h_i$），使长宽比惩罚与面积在同一数量级但权重较小

**直观含义**：优化器会优先追求面积最小；在两个面积相近的解中，选择长宽比更接近 1 的那个。

### 优化算法：模拟退火

#### 算法框架

```
1. 随机生成初始 B*-Tree T_best
   T = T₀, C_best = PACK(T_best).area + λ × (R-1)²
2. while T > T_final:
     for i = 1..K:           // 每温度 K 次迭代
       op = random_choice([Rotate, Swap, DeleteInsert, SubtreeMove])
       T_new = op(T_best)
       W, H, R = PACK(T_new)
       C_new = W × H + λ × (R-1)²
       ΔC = C_new - C_best
       if ΔC < 0 or random() < exp(-ΔC/T):
         T_best = T_new, C_best = C_new
     T = γ × T               // 降温
3. return (T_best, W_best, H_best, R_best, C_best)
```

#### 扰动操作（等概率随机选择）

| 操作 | 描述 | 复杂度 |
|------|------|--------|
| **Op1-旋转（Rotate）** | 随机选一节点，翻转其旋转标志位（交换宽高）| O(1) |
| **Op2-交换（Swap）** | 随机选两节点，交换在 B*-Tree 中的位置 | O(1) |
| **Op3-删除插入** | 随机删一节点，消除后在随机位置重新插入 | O(n) |
| **Op4-子树迁移** | 随机选一子树，整体迁移到另一位置 | O(n) |

#### 冷却策略

| 参数 | 设定 | 说明 |
|------|------|------|
| $T_0$ | 自适应（保证接受率 ≈ 95%）| 50 步随机扰动，统计 ΔE⁺ 均值反推 |
| $\gamma$ | 0.95 | 温度衰减系数 |
| $T_{final}$ | 0.01 | 终止温度 |
| $K$ | $50n$ | 每温度内循环次数 |
| 早停 | 连续 200 温度级无改善 | 避免无效迭代 |

### 优缺点

| 优点 | 缺点 |
|------|------|
| 编码紧凑 O(n)，无冗余表示 | B*-Tree 非完备表示（无法覆盖所有非 compact packing）|
| 单次 packing O(n)，迭代效率极高 | $n > 200$ 时收敛效率显著下降 |
| SA 实现简单，调参成本低 | 对初始解和冷却策略敏感 |
| 参考文献充分，学术认可度高 | 扰动对拓扑影响非线性，不易跳出某些局部最优 |

### 复杂度分析

- 单次 packing：**O(n)** 时间，**O(n)** 空间（轮廓线数组 + B*-Tree 节点存储）
- SA 总时间：$O(K_{temps} \cdot K \cdot n)$，$K_{temps} \approx \log_\gamma(T_f/T_0) \approx 500$
- 以 $n=30$ 为例：约 $500 \times 1500 \times 30 \approx 2.25 \times 10^7$ 次基本操作，约 **10 秒**

### 论文写作要点

- 强调 B*-Tree 的**无冗余性**：每个 packing 对应唯一编码，解空间无重复探索，与 SP 对比突出搜索效率
- 可引入**自适应冷却**：根据接受率动态调整 $\gamma$，高温区快冷、低温区慢冷，体现算法理论深度
- 轮廓线数据结构可用**红黑树实现**将 packing 降至 $O(n \log n)$，作为时间复杂度优化贡献点

## 方案2：序列对（Sequence Pair）+ SA — 表示对比

### 核心思路

序列对用两个 $n$ 排列 $(\Gamma^+, \Gamma^-)$ 编码模块相对位置，通过水平/垂直约束图的最长路径算法解码坐标。**解空间完备**（$n!^2$ 种编码，全覆盖所有可行布局且无冗余）。以 SA 在序列对空间搜索。

### 拓扑表示：Sequence Pair

**相对位置判定规则**（"同序定左右、逆序定上下"）：对任意两模块 $a, b$：

- $a$ 在 $b$ **左侧** $\iff$ $a$ 在 $\Gamma^+$ 和 $\Gamma^-$ 中**均在** $b$ 之前
- $a$ 在 $b$ **上方** $\iff$ $a$ 在 $\Gamma^+$ 中在 $b$ 之前，但在 $\Gamma^-$ 中在 $b$ 之后

**SP → 坐标转换** $O(n^2)$：

1. 遍历所有模块对 $(i, j)$，建立水平约束图 HCG（$i$ 在 $j$ 左侧 $\implies$ 有向边 $i \to j$）和垂直约束图 VCG（$i$ 在 $j$ 下方 $\implies$ 有向边 $i \to j$）
2. 添加虚拟源 $s$ 和虚拟汇 $t$
3. HCG 上最长路径算法（DAG 拓扑排序 + DP）→ $x$ 坐标
4. VCG 上最长路径算法 → $y$ 坐标
5. $W$ = 汇节点在 HCG 中最长路径长度，$H$ = 汇节点在 VCG 中最长路径长度

### 扰动操作

| 操作 | 描述 |
|------|------|
| M1 | 在 $\Gamma^+$ 或 $\Gamma^-$ 中交换随机两个模块 |
| M2 | 在两个序列中**同时**交换同一对模块 |
| M3 | 随机旋转一个模块 (交换宽高) |

### 优缺点

| 优点（vs B*-Tree）| 缺点（vs B*-Tree）|
|------|------|
| 解空间完备，能覆盖所有可行布局 | 单次解码 $O(n^2)$ vs $O(n)$ |
| 拓扑表示与模块尺寸无关，适合软模块 | 解空间 $n!^2$ 巨大，收敛慢 |
| 扰动操作简单对称 | 缺少"紧凑布局"结构偏好，依赖面积目标间接引导 |

### 复杂度分析

- 单次解码：$O(n^2)$（构造约束图 + 最长路径）
- SA 总时间：约 $O(K_{temps} \cdot K \cdot n^2)$
- 以 $n=30$ 为例：约 **60 秒**（方案1 的 6 倍）
- 可引入 **Fast SP**（LCS 加速）：$O(n \log \log n)$ 解码

### 论文对比作用

$$
\begin{aligned}
\text{若 } A_2 &< A_1 \text{ 显著} \implies \text{B*-Tree 有表达盲区，需改进表示} \\
\text{若 } A_2 &\approx A_1 \implies \text{B*-Tree 表示充分，验证方案1 的有效性}
\end{aligned}
$$

## 方案3：B*-Tree + 遗传算法（GA）— 算法对比

### 核心思路

仍用 B*-Tree 拓扑表示，但以遗传算法替代 SA 作为搜索引擎。种群并行探索解空间，天然不易陷入局部最优。

### 染色体编码

- **排列编码**：$n$ 个模块的前序遍历序列 → 长度 $n$ 的整数排列染色体
- **旋转附加编码**：$n$ 位二进制串（0=原朝向，1=旋转 90°）
- 总染色体长度 $2n$，排列总可解码为合法 B*-Tree（编码天然保证合法性）

### 遗传操作

| 操作 | 方法 | 说明 |
|------|------|------|
| **选择** | 锦标赛选择（size=2~5）| 精英保留 5%~10% |
| **交叉** | B*-Tree 子树交换 | 父A取子树 → 与父B对应子树交换 → 修复多余/缺失模块 |
| **变异** | ① 交换两模块位置 ② 翻转旋转位 | 陷入停滞时加大变异率 + 随机删除插入 |

### 适应度函数

$$
F(T) = W \times H + \lambda \cdot (R - 1)^2
$$

其中 $R = \max(W, H) / \min(W, H)$，$\lambda$ 同方案1。副目标长宽比惩罚确保在面积相近的布局中选择形状更接近正方形的。

### 参数设置

| 参数 | 值（n≤50）| 值（n>50）|
|------|-----------|----------|
| 种群规模 $P$ | 100~200 | 200~500 |
| 交叉概率 $p_c$ | 0.8 | 0.8 |
| 变异概率 $p_m$ | 0.1 | 0.1 |
| 精英比例 | 10% | 5% |
| 迭代代数 | 200~500 | 300~800 |
| 早停条件 | 连续 10 代 < 1% 改进 | 同左 |

### 优缺点

| 优点（vs SA）| 缺点（vs SA）|
|------|------|
| 隐式并行搜索，多方向同时探索 | 收敛速度慢于 SA，种群评估计算量大 |
| 种群多样性抵御局部最优 | 参数多（$P, p_c, p_m$, 精英率），调参成本高 |
| 天然适配多目标升级（NSGA-II）| 锦标赛选择对适应度尺度敏感 |

### 复杂度分析

- 种群规模 $P$，代数 $G$，单代复杂度 $O(P \cdot n)$
- 总时间：$O(G \cdot P \cdot n)$
- 以 $n=30, P=150, G=300$ 为例：约 **30 秒**

### 论文对比作用

$$
\begin{aligned}
\text{若 } A_3 &\ll A_1 \implies \text{SA 单点搜索严重陷入局部最优} \\
\text{若 } A_3 &\approx A_1 \implies \text{SA 已足够好，GA 的额外计算不必要}
\end{aligned}
$$

## 方案4：贪心构造 + 局部搜索 — 快速 Baseline

### 核心思路

以**确定性贪心策略**直接构造初始 B*-Tree（非随机），再以 2-opt 风格邻域扰动做局部搜索。在 100 模块以内可达 SA 的 80%~90% 质量，耗时仅 SA 的 1/5。定位为**确定性下界基准**。

### 贪心构造策略

**模块排序**：按"线网度 (net degree) 降序 × 面积权重"得分排序

- 线网度高的模块优先放置 → 互联密集模块聚集
- 面积大的模块次优先 → 避免大模块后期无处安放

**B*-Tree 贪心插入**（最佳适应下降法）：

```
1. 按排序顺序逐模块插入
2. 每模块在 B*-Tree 中尝试所有合法插入位置 + 两个旋转方向
3. 选择使当前包围矩形面积增量最小的位置
4. 复杂度 O(n²)
```

### 局部搜索

从贪心 B*-Tree 出发，每次随机执行以下操作之一：

1. 交换两模块位置（Swap）
2. 翻转单个模块方向（Rotate）
3. 删除当前节点后最优重插

面积减少则接受，否则回退。停止条件：连续 $n^2$ 步无改善。

### 优缺点

| 优点 | 缺点 |
|------|------|
| 执行极快（O(n²) 级），结果可复现 | 容易陷入局部最优 |
| 论文中作为对照组，展示启发式提升幅度 | 模块形状差异大时贪心排序可能误导 |
| 工程价值：秒级出可行解，快速评估可行性 | 纯确定性，无随机探索能力 |

### 复杂度

- 贪心构造：$O(n^2)$（每模块扫描轮廓线 O(n) 候选位置）
- 局部搜索：$O(n^2)$（迭代 O(n log n) 步 × O(n) 更新）
- 总空间：$O(n)$
- 以 $n=30$ 为例：约 **1 秒**

### 论文定位

```
贪心 baseline 面积 = 下界

启发式提升率 = (A_greedy - A_SA) / A_greedy × 100%
```

让读者看到"贪心已能达到什么水平，启发式在此基础上提升了多少"。

## 融合方案：Memetic 四阶段混合算法

### 融合思路

不搞"平等拼接"。选定 **B*-Tree + Memetic Algorithm（GA 内嵌 SA）** 为主骨架，将贪心、SP、纯 SA 分别嵌入四个关键节点。

```
贪心(方案4) ──注入──→ 阶段1：结构化初始种群
                          ↓
B*-Tree GA + 内嵌短SA ──→ 阶段2：Memetic 搜索主体
                          ↓
精英解 + 完整SA + SP跳跃 ──→ 阶段3：深度精炼
                          ↓
确定性LS ──→ 阶段4：扫尾
```

### 阶段1：贪心注入初始化（方案4 → 方案3）

```
1. 贪心+LS 跑出一个可行解 S_greedy，编码为 B*-Tree T₀
2. 种群生成：
   pop[0] = T₀  （贪心解保底）
   for i = 1 to POP_SIZE-1:
     k = ceil(i × K_max / POP_SIZE)   // 扰动次数梯度递增
     pop[i] = T₀.copy()
     for j = 1 to k:
       pop[i] = RANDOM_PERTURB(pop[i])
```

**设计要点**：扰动次数从 1 到 K_max（≈ 3n）梯度分布，形成"以贪心为中心、向外扩散"的初始种群。

**贪心初始化是否锁在局部？——否。** SA 的马尔可夫链在 $T > 0$ 时不可约，高初始温度下链会"忘记"初始状态。贪心只是跳过了高温修复可行性的浪费阶段。只要 $T_0$ 足够高（接受率 ~0.85），初期仍有大量上山移动。

### 阶段2：Memetic GA — 内嵌短 SA（方案3 + 方案1）

不采用"先 GA 后 SA"的串联方式，而是每个子代在进入种群前经过**短 SA 精炼**（Lamarckian 策略）：

```
每代流程：
1. 锦标赛选择 → 父母池
2. B*-Tree 子树交叉 → 子代
3. 变异（节点交换 + 旋转）
4. ★ 短SA精炼：对每个子代跑 50 次 SA 迭代
   - T_short = 自适应设定（接受率 ≈ 0.85）
   - α_short = 0.9（快冷）
   - 只做 B*-Tree 邻域扰动（O(n) 解码）
5. 精英保留(2个) + 轮盘赌替换 → 新一代
```

**为什么内嵌 > 串联**：

| | 串联式 | 内嵌式（Memetic）|
|------|------|------|
| GA阶段 | 无局部搜索，种群在次优区域徘徊 | 每个子代经过SA精炼后再进入种群 |
| 选择压力 | 作用在原始解上 | 作用在**精炼后**的解上 |
| 收敛效率 | 需要更多代数 | 代数少但每代质量高 |

### 阶段3：精英完整 SA + SP 跳跃（方案1 + 方案2）

从最终种群取前 $K=3$ 个精英，各自跑完整 SA。**SP 不作为主表示，只作为跳跃算子**：

| | B*-Tree 邻域（99%迭代）| SP 跳跃（1%迭代）|
|------|------|------|
| 每次解码 | O(n) | O(n²) |
| 作用 | 主力搜索 | "拓扑逃逸"，防表示盲区 |
| 1000次总成本 | 990n | 10n² |

```
SP跳跃算子（每 M=100 次正常迭代执行一次）：

1. T_curr 解码为坐标 → 提取 SP (Γ⁺, Γ⁻)            // O(n)
2. 在 Γ⁺ 中随机交换两个模块位置                      // O(1)
3. SP 解码为新布局，计算目标函数                     // O(n²)
4. 按 Metropolis 准则决定是否接受
5. 若接受：SP 转回 B*-Tree → T_new                  // O(n²)
```

SA 参数：$\alpha=0.98$（慢冷），$L_k=100$，$T_f=T_0/1000$。

### 阶段4：LS 扫尾（方案4）

对最终解做确定性 LS：遍历所有模块对，尝试交换/旋转/移动，接受任何改进，至局部最优。$O(n^2)$，只执行一次。

### 复杂度总览

| 阶段 | 操作 | 复杂度 | 占总预算 |
|------|------|--------|---------|
| 1 | 贪心 + 种群生成 | $O(n \log n + P \cdot n)$ | < 1% |
| 2 | Memetic GA 主循环 | $O(G \cdot P \cdot L_{short} \cdot n)$ | **~65%** |
| 3 | 精英 SA + SP 跳跃 | $O(K \cdot N_{temp} \cdot L_k \cdot (n + n^2/M))$ | ~34% |
| 4 | LS 扫尾 | $O(n^2)$ | < 1% |

**以 $n=50$ 为例**：$P=30$, $G=100$, $L_{short}=50$ → 约 $3 \times 10^7$ 次操作，约 **5 秒**（Python，含 JIT 加速）。

### 模拟退火核心循环

```python
def simulated_annealing(modules, lamb=0.05, T0=1e6, alpha=0.95,
                         T_final=1e-2, K=None, max_no_improve=200):
    n = len(modules)
    if K is None:
        K = 50 * n

    A_min = sum(m.w * m.h for m in modules)  # 面积理论下界
    lamb_scaled = lamb * A_min               # 使惩罚与面积同量级

    def cost(W, H):
        R = max(W, H) / min(W, H)
        return W * H + lamb_scaled * (R - 1) ** 2

    T = T0
    tree = BTree(modules)
    tree.random_init()
    best_tree = tree.copy()
    W, H, R = tree.pack()
    best_cost = cost(W, H)
    no_improve = 0

    while T > T_final and no_improve < max_no_improve:
        for _ in range(K):
            # 随机选择扰动操作
            op = random.choice([rotate, swap, delete_insert, subtree_move])
            new_tree = op(tree)

            W, H, R = new_tree.pack()
            new_cost = cost(W, H)
            delta = new_cost - best_cost

            if delta < 0 or random.random() < math.exp(-delta / T):
                tree = new_tree
                if new_cost < best_cost:
                    best_tree = tree.copy()
                    best_cost = new_cost
                    no_improve = 0
        T *= alpha
        no_improve += 1

    return best_tree, best_cost
```
