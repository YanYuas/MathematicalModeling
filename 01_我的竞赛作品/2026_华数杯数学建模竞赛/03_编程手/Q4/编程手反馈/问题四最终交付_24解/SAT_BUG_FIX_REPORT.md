# SAT Bug修复报告

## 问题描述

**原始结果**：最小包络面积30（6×5），死区20%  
**修复后结果**：最小包络面积24（6×4），死区0%（完美平铺）

## 根本原因

原重叠检测使用**分离轴定理（SAT）**变体：
- 边相交检测
- 顶点包含检测

**Bug现象**：在共线贴边（两个多边形边界共线但不重叠）时误判为重叠

**示例**：
```
模块A: 边界在 x=4
模块B: 边界在 x=4（左侧贴边）
SAT判定：顶点 (4, y) 在对方边界上 → 误判为重叠
实际：两模块完美贴边，无重叠
```

## 修复方案

采用**单位格法（Unit Grid Method）**：

### 算法原理
1. 将两个多边形应用偏移得到全局坐标
2. 计算覆盖区域的整数格点范围
3. 遍历每个格点的中心（x+0.5, y+0.5）
4. 检查格点中心是否同时在两个多边形内部
5. 如果存在这样的格点 → 重叠，否则 → 分离

### 优点
- **共线贴边友好**：贴边不会导致格点中心同时在两个多边形内
- **精确性**：对正交多边形（顶点为整数坐标）是精确的
- **简单性**：避免SAT的边界判定复杂性
- **适用性**：天然支持凹多边形（T型、L型）

### 代码对比

**修复前（SAT）**：
```python

    # ... AABB粗判 ...
    # 边相交检测
    for i in range(nA):
        for j in range(nB):
            if seg_intersect(p1, p2, p3, p4, eps):
                return True
    # 顶点包含检测（共线贴边时误判）
    for v in Ash:
        if point_in_poly(v[0], v[1], Bsh, eps): 
            return True  # BUG: 边界上的点被判定为"在内部"
    return False
```

**修复后（单位格法）**：
```python
def polys_overlap(vertsA, offA, vertsB, offB, eps=1e-9):
    # ... AABB粗判 ...
    # 遍历整数格点
    for x in range(minx, maxx + 1):
        for y in range(miny, maxy + 1):
            cx, cy = x + 0.5, y + 0.5  # 格点中心
            in_A = point_in_poly(cx, cy, Ash, eps)
            in_B = point_in_poly(cx, cy, Bsh, eps)
            if in_A and in_B:
                return True  # 同一格点被两个多边形占用
    return False  # 贴边时格点中心不会同时被占用
```

## 理论分析

### 为什么SAT会误判？

SAT的顶点包含检测使用射线法（Ray Casting）：
- 从点P向右发射射线
- 统计与多边形边界的交点数
- 奇数 → 内部，偶数 → 外部
- **边界上的点**：特殊处理，通常判定为"在内部"

**问题**：当两个多边形共线贴边时，边界点被双方都判定为"在内部" → 误判为重叠

### 为什么单位格法不会误判？

**关键**：检查格点**中心**（x+0.5, y+0.5），而非格点**顶点**
- 贴边时：边界在整数坐标（如x=4）
- 格点中心：在半整数坐标（如x=3.5或x=4.5）
- **格点中心永远不会在边界上** → 不会同时被两个贴边多边形包含

## 建议

1. **对于正交多边形布局问题**：优先使用单位格法
2. **对于一般多边形**：需要更精细的SAT实现或其他方法（如GJK）
3. **代码审查**：边界条件测试应包含共线贴边场景
