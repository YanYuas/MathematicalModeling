## 一、实验设置

### 对比内容
1. 纯递归 vs 记忆化搜索 vs 迭代DP（斐波那契）
2. 二维DP vs 一维滚动数组（0-1背包）
3. O(n²) DP vs O(n log n) 贪心二分（LIS）
4. 不同规模下的性能（编辑距离、矩阵链）

### 实验环境
- Python 3.x，NumPy
- 固定随机种子42，保证可复现

## 二、实验结果

### 实验1：斐波那契三种方法对比

| n | 纯递归(ms) | 记忆化(ms) | 迭代DP(ms) | 递归/DP |
|---|-----------|-----------|-----------|---------|
| 10 | 0.019 | 0.008 | 0.004 | 5x |
| 20 | 1.032 | 0.004 | 0.001 | 866x |
| 30 | 97.405 | 0.013 | 0.003 | 34,046x |
| 35 | 978.173 | 0.018 | 0.005 | **186,489x** |

**关键发现**：
- 纯递归是O(2^n)指数爆炸，n=35时需要近1秒
- 记忆化搜索和迭代DP都是O(n)，几乎不随n增长
- n=35时，递归比DP慢了**18.6万倍**！

💡 **顿悟**：这就是动态规划最直观的威力——把指数级复杂度降到线性。同一个问题，写对方法和写错方法，性能差几个数量级。

### 实验2：0-1背包 —— 二维 vs 一维

| 物品数 | 容量 | 二维(ms) | 一维(ms) | 空间比 | 结果一致 |
|--------|------|---------|---------|--------|---------|
| 10 | 50 | 0.056 | 0.025 | 10x | ✓ |
| 50 | 200 | 0.972 | 0.513 | 50x | ✓ |
| 100 | 500 | 5.677 | 3.120 | 100x | ✓ |
| 200 | 1000 | 24.088 | 13.250 | 200x | ✓ |

**关键发现**：
- 一维滚动数组空间从O(nW)降到O(W)，省了n倍
- 一维速度也更快（约2倍），因为缓存更友好
- 结果完全一致

⚠️ **坑**：一维优化时j必须逆序遍历！如果正序，同一个物品会被选多次（变成完全背包）。这是初学者最容易犯的错误。

### 实验3：LIS —— O(n²) vs O(n log n)

| n | DP O(n²)(ms) | 二分O(nlogn)(ms) | 速度比 | 结果一致 |
|---|-------------|-----------------|--------|---------|
| 100 | 0.474 | 0.026 | 18x | ✓ |
| 500 | 5.351 | 0.082 | 65x | ✓ |
| 1000 | 22.270 | 0.169 | 132x | ✓ |
| 5000 | 506.414 | 0.853 | 594x | ✓ |
| 10000 | 1921.246 | 1.737 | **1,106x** | ✓ |

**关键发现**：
- n=10000时，O(n²)需要近2秒，O(n log n)只需1.7毫秒
- 速度比随n增大而增大（理论上是n/logn倍）
- 两种方法结果完全一致（LIS长度相同，具体序列可能不同）

💡 **顿悟**：算法复杂度决定大数据量下的生死。n=100时两种方法差不多，n=10000时差了1000倍。比赛中如果n很大，必须选对复杂度。

### 实验4：编辑距离

| 长度 | 时间(ms) | 空间(KB) | 编辑距离 |
|------|---------|---------|---------|
| 50 | 0.376 | 20.3 | 29 |
| 100 | 1.369 | 79.7 | 59 |
| 200 | 5.592 | 315.6 | 114 |
| 500 | 36.416 | 1960.9 | 274 |

**分析**：编辑距离是O(mn)时间和空间。n=500时空间约2MB，还可以接受。但如果是全基因组比对（百万级），就需要更高级的算法（如BLAST的种子扩展策略）。

### 实验5：矩阵链乘法

| 矩阵数 | 时间(ms) | 最少乘法次数 |
|--------|---------|-------------|
| 5 | 0.033 | 387,408 |
| 10 | 0.039 | 403,546 |
| 20 | 0.220 | 763,576 |
| 50 | 2.847 | 1,672,617 |
| 100 | 21.724 | 2,791,058 |

**分析**：矩阵链是O(n³)，n=100时22ms。实际应用中矩阵数量通常不多（<20），所以这个算法完全够用。

## 三、动态规划的"能"与"不能"

### 能解决的问题
- 有最优子结构 + 重叠子问题
- 状态空间是多项式级别的（n², n³等）
- 决策是离散的、有限的

### 不能（或不适合）解决的问题
- 状态空间指数级（如TSP n>20，2^n太大）
- 没有最优子结构（如最长简单路径）
- 子问题不重叠（如归并排序，用分治更好）
- 连续状态空间（需要离散化或用其他方法）

### DP的边界
| 问题 | 状态数 | DP可行？ |
|------|--------|---------|
| 背包 n=100, W=1000 | 10^5 | ✓ |
| LCS n=1000 | 10^6 | ✓ |
| 编辑距离 n=1000 | 10^6 | ✓ |
| TSP n=15 | 2^15≈3万 | ✓ |
| TSP n=20 | 2^20≈100万 | ✓（勉强） |
| TSP n=30 | 2^30≈10亿 | ✗ 用启发式 |

## 四、对建模比赛的建议

### 1. 什么时候用DP？
- 问题可以拆成阶段，每个阶段做决策
- 有"最优子结构"的感觉
- 暴力递归会重复计算很多子问题

### 2. DP的解题套路
1. **先写暴力递归**：不管效率，先写对
2. **加记忆化**：发现重复计算，加字典存储
3. **改迭代**：从底往上算，避免递归栈溢出
4. **优化空间**：看能不能用滚动数组降维
5. **考虑更优算法**：如果n很大，看有没有O(n log n)的优化

### 3. 常见DP类型速查
| 题目关键词 | 可能的DP类型 |
|-----------|-------------|
| "最大价值""背包""容量" | 背包DP |
| "最长公共""子序列""匹配" | 序列DP（LCS/编辑距离） |
| "最长递增""上升" | LIS（O(n²)或O(nlogn)） |
| "区间""合并""石子" | 区间DP |
| "网格""路径""只能向右向下" | 网格DP |
| "状态""集合""选了哪些" | 状态压缩DP |
| "多阶段""决策""库存" | 多阶段决策DP |
| "概率""期望""随机" | 概率DP / MDP |

### 4. 调参和优化
- 空间不够：用滚动数组、状态压缩
- 时间不够：看能不能优化转移（单调队列、斜率优化、四边形不等式）
- 状态太多：考虑只算需要的状态（记忆化搜索）
- 结果不对：检查初始条件、边界、计算顺序

## 五、后续研究方向

✨ **创新点1：DP + 机器学习**
用神经网络近似状态价值函数（如AlphaGo的价值网络），解决状态空间太大的问题。这是强化学习的基础。

✨ **创新点2：并行DP**
某些DP问题可以并行计算（如矩阵链的不同区间、网格的不同对角线），利用GPU加速。

✨ **创新点3：近似DP**
状态空间太大时，用函数近似代替精确DP，在精度和效率间权衡。

✨ **创新点4：自动DP生成**
给定问题描述，自动识别DP结构并生成代码（AI辅助算法设计）。
