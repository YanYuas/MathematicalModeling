# 建模手研究体系 · 总纲

> 不是资料的搬运工，而是算法的钻研者。
> 从"知道这个算法"到"理解这个算法"再到"玩转这个算法"。

---

## 一、为什么要建立自己的研究体系？

### 1.1 痛点
- 课件看了很多，但合上书就忘
- 代码跑通了，但不知道为什么这么写
- 遇到新问题，不知道该用哪个算法
- 论文里写的模型，自己复现不出来

### 1.2 根源
- 停留在"认知"层面，没有进入"理解"层面
- 没有亲手推导过公式，只是在背结论
- 没有踩过坑，不知道算法的边界在哪里
- 没有对比过，不知道每个算法的"性格"

### 1.3 目标
建立一套**自己的**、**可复用的**、**有深度的**算法研究体系：
- 每个算法都能讲清楚"为什么"
- 每个算法都能从零写出来
- 遇到新问题能快速判断用什么方法
- 能在现有算法基础上做改进和组合

## 二、六层钻研法

每个算法都按照以下六层逐步深入，缺一不可。

### 第1层：问题起源
**回答：这个算法为什么会被发明？**
- 当时的人遇到了什么问题？
- 之前的方法为什么不行？
- 这个算法的核心突破是什么？

> 例：单纯形法为什么被发明？因为线性规划在1940年代被提出，但没有高效求解方法，Dantzig在1947年提出了单纯形法，核心突破是"从一个顶点跳到更优顶点"。

### 第2层：核心思想
**回答：用一句话讲透这个算法。**
- 用自己的话解释，不要用术语
- 找一个生活化的比喻
- 画一张直观的图（几何意义）

> 例：梯度下降的核心思想——"站在山坡上，往最陡的方向走一步，重复直到谷底"。

### 第3层：数学推导
**回答：关键公式是怎么来的？**
- 一步步推导，不跳步
- 每个符号的含义写清楚
- 推导过程中的假设和前提
- 自己的疑问和思考（写在旁边）

> 这一层最重要。抄书不算，必须自己推一遍。推不出来的地方就是知识盲区。

### 第4层：手动实现
**回答：不看参考，能从零写出来吗？**
- 先写伪代码，再写真实代码
- 每个函数的作用写清楚
- 用最简单的例子验证
- 记录调试过程中遇到的bug
- 对比自己的实现和库的实现差异

### 第5层：应用实战
**回答：遇到真实问题，怎么转化成这个算法？**
- 问题→模型的转化过程
- 建模中的常见坑
- 怎么判断这个算法适不适合
- 参数怎么调
- 结果怎么分析和解释

### 第6层：对比与创新
**回答：这个算法和其他算法比怎么样？我能怎么改进？**
- 横向对比：和同类算法比优缺点
- 纵向对比：和精确算法比差距在哪里
- 组合创新：能不能和其他算法结合？
- 改进方向：有什么可以优化的地方？

## 三、笔记规范

### 3.1 每个算法的笔记结构
```
# [算法名] 深研笔记

## 0. 我的一句话总结
（用自己的话，不超过50字）

## 1. 问题起源
- 历史背景
- 解决的痛点
- 核心突破

## 2. 核心思想
- 直观解释
- 比喻
- 几何意义

## 3. 数学推导
### 3.1 问题定义
### 3.2 关键推导
（一步步来，不跳步）
### 3.3 我的疑问
（推导中不懂的地方）

## 4. 算法流程
- 伪代码
- 复杂度分析

## 5. 手动实现
- 代码（带详细注释）
- 测试用例
- 调试记录

## 6. 应用实战
- 适用场景
- 建模技巧
- 常见坑

## 7. 对比与思考
- 和XX算法的对比
- 我的改进想法

## 8. 参考文献
- 看过的资料
```

### 3.2 标记系统
在笔记中使用以下标记：
- `💡 顿悟`：突然想明白的关键点
- `❓ 疑问`：还没搞懂的问题
- `⚠️ 坑`：踩过的坑，提醒自己
- `🔗 关联`：和其他算法/知识点的联系
- `✨ 创新`：自己的想法和改进

## 四、学习路径

### 4.1 优化模型的学习顺序
```
第一阶段：基础（必须吃透）
  线性规划 → 整数规划 → 非线性规划

第二阶段：进阶
  多目标规划 → 动态规划

第三阶段：高级
  遗传算法 → 模拟退火 → 粒子群
  → 蚁群算法 → 差分进化 → NSGA-II

第四阶段：融合
  算法对比 → 混合算法 → 针对问题的定制算法
```

### 4.2 每个算法的时间分配
- 第1-2层（起源+思想）：20%时间
- 第3层（数学推导）：30%时间（最重要）
- 第4层（手动实现）：20%时间
- 第5层（应用实战）：20%时间
- 第6层（对比创新）：10%时间

## 五、与现有资料的关系

### 5.1 老师课件的定位
- 是**输入素材**，不是最终成果
- 需要精读、消化、转化
- 课件中的结论要自己推导验证

### 5.2 代码模板的定位
- 是**参考实现**，不是自己的代码
- 需要先看懂，再关掉自己写
- 对比差异，理解为什么这么写

### 5.3 本体系的定位
- 是**输出成果**，是自己的东西
- 可以在比赛中直接复用
- 随着学习不断更新和深化
