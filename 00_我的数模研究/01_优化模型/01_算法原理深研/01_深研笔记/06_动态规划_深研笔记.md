## 一、问题起源

### 1.1 从一个简单问题开始

**斐波那契数列**：F(0)=0, F(1)=1, F(n)=F(n-1)+F(n-2)

如果用递归：
```python
def fib(n):
    if n <= 1: return n
    return fib(n-1) + fib(n-2)
```

计算fib(5)时：
- fib(5) = fib(4) + fib(3)
- fib(4) = fib(3) + fib(2)
- fib(3) = fib(2) + fib(1)
- ...

**问题**：fib(3)被计算了2次，fib(2)被计算了3次！大量重复计算。

时间复杂度：O(2^n) —— 指数爆炸！

### 1.2 动态规划的诞生

1953年，美国数学家Richard Bellman提出"动态规划"（Dynamic Programming）。

核心思想：**把大问题拆成小问题，把小问题的答案存起来，避免重复计算。**

💡 **顿悟**：动态规划不是一种具体算法，而是一种"解题思想"——用空间换时间，把指数级复杂度降到多项式级。

## 二、核心思想

### 2.1 两个必要条件

动态规划能解决的问题必须满足两个条件：

**条件1：最优子结构（Optimal Substructure）**
> 大问题的最优解，可以由小问题的最优解组合得到。

例：从A到C的最短路径 = 从A到B的最短路径 + B到C的最短路径。

**条件2：重叠子问题（Overlapping Subproblems）**
> 同一个小问题会被反复计算多次。

例：斐波那契中fib(3)被反复计算。

⚠️ **坑**：不是所有问题都能用动态规划！如果问题没有最优子结构（如最长简单路径），或者子问题不重叠（如归并排序），就不适合用DP。

### 2.2 两种实现方式

**方式1：记忆化搜索（自顶向下，Top-Down）**
- 从大问题出发，递归求解
- 每算出一个子问题的答案就存起来
- 下次遇到相同子问题直接查表
- 优点：直观、只算需要的子问题
- 缺点：递归有栈溢出风险

**方式2：迭代DP（自底向上，Bottom-Up）**
- 从最小的子问题开始，一步步往上算
- 用数组/表格存所有子问题的答案
- 优点：无递归、效率高
- 缺点：可能算一些不需要的子问题

💡 **顿悟**：两种方式本质一样，只是计算顺序不同。比赛中推荐迭代DP（更快更稳），思考时用记忆化（更直观）。

### 2.3 DP解题四步法

**第一步：定义状态**
- 用dp[i]或dp[i][j]表示什么？
- 状态是问题的"快照"，要能完整描述子问题

**第二步：写出状态转移方程**
- dp[i] 怎么由更小的 dp[j] 得到？
- 这是DP的核心，也是最难的一步

**第三步：确定初始条件和边界**
- dp[0] = ? dp[1] = ?
- 边界情况怎么处理？

**第四步：确定计算顺序和返回值**
- 从小到大还是从大到小？
- 最终答案是dp[n]还是max(dp)?

## 三、经典问题详解

### 3.1 0-1背包问题

**问题**：有n个物品，第i个物品重量w[i]，价值v[i]。背包容量W，每个物品只能选或不选，求最大价值。

**状态定义**：dp[i][j] = 前i个物品，背包容量j时的最大价值

**状态转移**：
```
dp[i][j] = max(
    dp[i-1][j],              # 不选第i个物品
    dp[i-1][j-w[i]] + v[i]   # 选第i个物品（j>=w[i]时）
)
```

**初始条件**：dp[0][j] = 0（没有物品，价值为0）

**答案**：dp[n][W]

**空间优化（滚动数组）**：
观察到dp[i]只依赖dp[i-1]，可以用一维数组：
```python
dp = [0] * (W + 1)
for i in range(n):
    for j in range(W, w[i]-1, -1):  # 注意：逆序！
        dp[j] = max(dp[j], dp[j-w[i]] + v[i])
```

⚠️ **坑**：一维优化时必须逆序遍历j！如果正序，同一个物品会被选多次（变成完全背包）。

**复杂度**：
- 时间：O(nW)
- 空间：O(W)（优化后）

### 3.2 完全背包问题

**问题**：每个物品可以选无限次。

**状态转移**：
```
dp[i][j] = max(
    dp[i-1][j],
    dp[i][j-w[i]] + v[i]  # 注意：是dp[i]不是dp[i-1]！
)
```

**一维优化**：正序遍历j
```python
for j in range(w[i], W+1):  # 正序！
    dp[j] = max(dp[j], dp[j-w[i]] + v[i])
```

💡 **顿悟**：0-1背包逆序，完全背包正序。区别就在于"同一个物品能不能重复选"。

### 3.3 最长公共子序列（LCS）

**问题**：两个字符串A和B，求最长的公共子序列（不要求连续）。

例：A="ABCBDAB", B="BDCAB" → LCS="BCAB"，长度4

**状态定义**：dp[i][j] = A前i个字符和B前j个字符的LCS长度

**状态转移**：
```
如果 A[i-1] == B[j-1]:
    dp[i][j] = dp[i-1][j-1] + 1
否则:
    dp[i][j] = max(dp[i-1][j], dp[i][j-1])
```

**初始条件**：dp[0][j] = dp[i][0] = 0

**答案**：dp[m][n]

**回溯求具体序列**：从dp[m][n]往回走，相等就取该字符，否则往大的方向走。

**复杂度**：O(mn)时间，O(mn)空间（可优化到O(min(m,n))）

### 3.4 最长递增子序列（LIS）

**问题**：数组中最长的递增子序列。

例：[10, 9, 2, 5, 3, 7, 101, 18] → LIS=[2, 3, 7, 101]，长度4

**方法1：DP（O(n²)）**
```
dp[i] = 以第i个元素结尾的LIS长度
dp[i] = max(dp[j] + 1) for j < i and nums[j] < nums[i]
答案 = max(dp)
```

**方法2：贪心+二分（O(n log n)）**
维护一个tails数组，tails[i]表示长度为i+1的递增子序列的最小末尾。
每个元素用二分查找插入位置。

💡 **顿悟**：LIS的O(n log n)解法不是纯DP，是DP+贪心的结合。比赛中如果n很大（>10^4），必须用这个优化。

### 3.5 编辑距离（Levenshtein Distance）

**问题**：把字符串A变成B，最少需要多少次操作（插入、删除、替换）？

**状态定义**：dp[i][j] = A前i个字符变成B前j个字符的最少操作数

**状态转移**：
```
如果 A[i-1] == B[j-1]:
    dp[i][j] = dp[i-1][j-1]  # 不用操作
否则:
    dp[i][j] = 1 + min(
        dp[i-1][j],    # 删除A[i-1]
        dp[i][j-1],    # 插入B[j-1]
        dp[i-1][j-1]   # 替换A[i-1]为B[j-1]
    )
```

**初始条件**：dp[i][0] = i（全删），dp[0][j] = j（全插）

**复杂度**：O(mn)

### 3.6 矩阵链乘法

**问题**：n个矩阵相乘，不同的结合顺序计算量不同，求最优结合顺序。

例：A(10×100) × B(100×5) × C(5×50)
- (AB)C = 10×100×5 + 10×5×50 = 5000 + 2500 = 7500
- A(BC) = 100×5×50 + 10×100×50 = 25000 + 50000 = 75000
差了10倍！

**状态定义**：dp[i][j] = 矩阵i到矩阵j相乘的最少计算量

**状态转移**：
```
dp[i][j] = min(dp[i][k] + dp[k+1][j] + p[i-1]*p[k]*p[j])
           for k in [i, j-1]
```
其中p[i-1]是矩阵i的行数，p[k]是矩阵k的列数=矩阵k+1的行数。

**计算顺序**：按区间长度从小到大算（长度2, 3, ..., n）

**复杂度**：O(n³)时间，O(n²)空间

## 四、动态规划的分类

### 4.1 按状态维度分

| 类型 | 特点 | 例子 |
|------|------|------|
| 一维DP | dp[i] | 爬楼梯、打家劫舍 |
| 二维DP | dp[i][j] | 背包、LCS、编辑距离 |
| 区间DP | dp[i][j]表示区间[i,j] | 矩阵链、石子合并 |
| 树形DP | dp[node]在树上 | 树的最大独立集 |
| 状态压缩DP | 用二进制表示状态 | 旅行商问题TSP |
| 数位DP | 按位统计 | 统计[1,N]中含某数字的数 |
| 概率DP | dp[i]表示概率/期望 | 随机游走、骰子游戏 |

### 4.2 按优化技巧分

| 技巧 | 适用场景 | 原理 |
|------|---------|------|
| 滚动数组 | dp[i]只依赖dp[i-1] | 二维降一维 |
| 状态压缩 | 状态数多但每个维度小 | 用二进制位表示 |
| 单调队列优化 | 转移方程含滑动窗口最值 | 用队列维护最值 |
| 斜率优化 | 转移方程可写成y=kx+b形式 | 用凸包维护最优决策 |
| 四边形不等式 | 满足四边形不等式的区间DP | 决策点单调，降一维 |

## 五、与其他方法的关系

### 5.1 DP vs 贪心

| | 动态规划 | 贪心 |
|---|---------|------|
| 决策 | 考虑所有可能，选最优 | 只看当前最优 |
| 最优性 | 保证全局最优 | 不一定全局最优 |
| 效率 | 较慢（多项式） | 快（线性） |
| 适用 | 有最优子结构+重叠子问题 | 有贪心选择性质 |

💡 **关联**：有些问题两种方法都能解（如活动选择），但DP更通用。贪心可以看作DP的"偷懒版"——如果能证明贪心选择性质，就不用枚举所有状态了。

### 5.2 DP vs 分治

| | 动态规划 | 分治 |
|---|---------|------|
| 子问题 | 重叠（反复计算） | 独立（不重叠） |
| 存储 | 需要存子问题答案 | 不需要 |
| 例子 | 斐波那契、背包 | 归并排序、快速排序 |

### 5.3 DP vs 记忆化搜索

记忆化搜索就是"自顶向下的DP"。本质完全一样，只是实现方式不同。

## 六、建模比赛中的动态规划

### 6.1 常见应用场景

1. **资源分配**：有限资源分配给多个项目，求最大收益（背包变种）
2. **路径规划**：网格中找最短/最优路径（二维DP）
3. **序列分析**：DNA序列比对、时间序列模式（LCS/编辑距离）
4. **生产调度**：多阶段生产计划（多维DP）
5. **投资决策**：多期投资组合（动态决策）

### 6.2 比赛中的坑

⚠️ **坑1：状态定义不清**
状态要能完整描述子问题，不能有歧义。如果发现状态转移写不出来，通常是状态定义错了。

⚠️ **坑2：边界条件遗漏**
dp[0]、dp[i][0]、空集等边界情况要仔细处理。

⚠️ **坑3：计算顺序错误**
区间DP要按长度从小到大，背包一维优化要逆序。顺序错了结果就错。

⚠️ **坑4：空间溢出**
n=1000时二维DP是10^6个元素（OK），n=10000时是10^8（可能爆内存）。需要滚动数组优化。

⚠️ **坑5：把DP当万能药**
不是所有优化问题都能用DP。如果状态空间太大（如TSP n=20，状态2^20≈100万，还可以；n=30就10亿，不行了），需要用启发式算法。

## 七、个人研究笔记

### 💡 顿悟时刻

1. **DP的本质是"填表"**：不管什么DP问题，最终都是在填一张表。状态是格子，转移是格子间的关系。想清楚表怎么填，问题就解决了。

2. **状态定义是灵魂**：同一个问题可以有多种状态定义，好的定义让转移方程简单自然，差的定义让转移复杂甚至写不出来。

3. **从暴力递归到DP的路径**：先写暴力递归 → 发现重叠子问题 → 加记忆化 → 改成迭代DP。这是最稳妥的解题路径。
