## 一、问题起源

### 1.1 什么是网络优化？

网络优化研究的是**图（Graph）上的优化问题**。图由节点（Vertex）和边（Edge）组成，边可以有权重（Weight）、容量（Capacity）、费用（Cost）等属性。

生活中的网络优化问题无处不在：
- 导航软件找最短路径 → 最短路问题
- 快递网点布局 → 最小生成树
- 水管最大流量 → 最大流问题
- 运输调度最小成本 → 最小费用流
- 任务分配给工人 → 二分图匹配

### 1.2 图的基本概念

**图的表示**：G = (V, E)，V是节点集合，E是边集合。

**有向图 vs 无向图**：
- 无向图：边没有方向，A→B和B→A是同一条边
- 有向图：边有方向，A→B和B→A是不同的边

**权重**：每条边可以有一个数值，表示距离、费用、容量等。

**图的存储方式**：
1. **邻接矩阵**：n×n矩阵，matrix[i][j]表示i到j的边权
   - 优点：查询快O(1)
   - 缺点：空间O(n²)，稀疏图浪费
2. **邻接表**：每个节点存一个列表，记录相邻节点和边权
   - 优点：空间O(n+m)，适合稀疏图
   - 缺点：查询需要遍历列表

## 二、最短路径问题

### 2.1 问题描述
给定图G=(V,E)和源点s，求s到所有其他节点的最短路径。

### 2.2 Dijkstra算法（单源最短路，非负权）

**核心思想**：贪心——每次选距离源点最近的未访问节点，用它更新其他节点的距离。

**算法步骤**：
1. 初始化：dist[s]=0，其他节点dist=∞
2. 重复n次：
   a. 选未访问中dist最小的节点u
   b. 标记u为已访问
   c. 对u的每条边(u,v,w)：dist[v] = min(dist[v], dist[u]+w)

**时间复杂度**：
- 朴素实现：O(n²)
- 优先队列优化：O(m log n)

**适用条件**：所有边权非负。

⚠️ **坑**：Dijkstra不能处理负权边！因为贪心策略在负权下会失效。

### 2.3 Bellman-Ford算法（单源最短路，可负权）

**核心思想**：动态规划——每条边最多松弛n-1次。

**算法步骤**：
1. 初始化dist[s]=0，其他=∞
2. 重复n-1次：对每条边(u,v,w)，dist[v] = min(dist[v], dist[u]+w)
3. 再做一次，如果还能更新，说明有负权环

**时间复杂度**：O(nm)

**优点**：可以处理负权边，可以检测负权环。
**缺点**：比Dijkstra慢。

### 2.4 Floyd-Warshall算法（全源最短路）

**核心思想**：动态规划——考虑中间节点。

**状态定义**：dist[k][i][j] = 从i到j，只经过前k个节点作为中间点的最短距离。

**状态转移**：
```
dist[k][i][j] = min(dist[k-1][i][j],           不经过k
                    dist[k-1][i][k] + dist[k-1][k][j])  经过k
```

可以用滚动数组优化到二维：
```
for k in range(n):
    for i in range(n):
        for j in range(n):
            dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
```

**时间复杂度**：O(n³)
**空间复杂度**：O(n²)

💡 **顿悟**：Floyd的三重循环顺序很重要！k必须在最外层（中间节点），i和j在内层。如果顺序错了结果就错了。

### 2.5 三种最短路算法对比

| 算法 | 适用场景 | 时间复杂度 | 负权 | 全源 |
|------|---------|-----------|------|------|
| Dijkstra | 单源，非负权 | O(m log n) | ✗ | ✗ |
| Bellman-Ford | 单源，可负权 | O(nm) | ✓ | ✗ |
| Floyd | 全源 | O(n³) | ✓ | ✓ |

## 三、最小生成树（MST）

### 3.1 问题描述
给定无向带权图，选n-1条边，使所有节点连通，且总权重最小。

**性质**：
- 生成树有n-1条边
- 生成树没有环
- 最小生成树可能不唯一，但总权重唯一

### 3.2 Prim算法

**核心思想**：从一个节点出发，每次选连接"已选集合"和"未选集合"的最小边。

**算法步骤**：
1. 任选一个节点加入集合S
2. 重复n-1次：
   a. 找一端在S、一端不在S的最小边
   b. 把这条边和新节点加入S

**时间复杂度**：
- 朴素实现：O(n²)
- 优先队列优化：O(m log n)

**适合**：稠密图。

### 3.3 Kruskal算法

**核心思想**：把所有边按权重排序，从小到大依次选，如果不形成环就加入。

**算法步骤**：
1. 把所有边按权重从小到大排序
2. 依次遍历每条边：
   a. 如果这条边连接的两个节点不在同一集合（用并查集判断）
   b. 就把这条边加入生成树，合并两个集合
3. 直到选了n-1条边

**时间复杂度**：O(m log m)（主要是排序）

**适合**：稀疏图。

### 3.4 并查集（Union-Find）

Kruskal需要用到并查集来快速判断两个节点是否连通。

**核心操作**：
- find(x)：找x的根节点（带路径压缩）
- union(x,y)：合并x和y所在的集合

**路径压缩**：find时把路径上的节点直接指向根。
**按秩合并**：把小树合并到大树下，保持树平衡。

💡 **顿悟**：并查集是近乎O(1)的数据结构（实际是反阿克曼函数，增长极慢），是Kruskal算法高效的关键。

## 四、最大流问题

### 4.1 问题描述
给定有向图，每条边有容量c(u,v)。源点s不断流出，汇点t不断流入。求从s到t的最大流量。

**基本概念**：
- 容量c(u,v)：边最多能通过的流量
- 流量f(u,v)：实际通过的流量，0 ≤ f ≤ c
- 残量网络：剩余容量 = 容量 - 流量
- 增广路：从s到t的一条路径，每条边都有剩余容量

### 4.2 Ford-Fulkerson方法

**核心思想**：不断找增广路，直到找不到为止。

**关键**：反向边。增加一条边的流量时，同时增加反向边的残量，允许后续"反悔"（把流量退回去）。

### 4.3 Edmonds-Karp算法

Ford-Fulkerson的具体实现：用BFS找增广路。

**时间复杂度**：O(nm²)

### 4.4 Dinic算法（最常用）

**核心思想**：BFS分层 + DFS多路增广。

**算法步骤**：
1. BFS：从s出发，给每个节点标层次（距离s的边数）
2. DFS：在层次图上找增广路（只走层次+1的边），一次找多条
3. 重复1-2，直到BFS到不了t

**当前弧优化**：记录每个节点已经搜到哪条边了，避免重复搜索。

**时间复杂度**：O(n²m)，实际运行很快。

💡 **顿悟**：Dinic是比赛中最常用的最大流算法，因为实现不算复杂且效率高。BFS分层保证了每次增广路的长度递增，DFS多路增广提高了效率。

## 五、最小费用最大流

### 5.1 问题描述
在最大流的基础上，每条边还有费用（每单位流量的费用）。求流量最大的前提下，总费用最小。

### 5.2 连续最短路算法（SPFA + EK）

**核心思想**：每次找费用最小的增广路，而不是任意增广路。

**算法步骤**：
1. 用SPFA（可处理负权的Bellman-Ford队列优化）在残量网络上找s到t的最短路（费用为边权）
2. 沿这条最短路增广（增加流量）
3. 重复，直到找不到增广路

**为什么用SPFA而不是Dijkstra**：因为反向边的费用是负的（退流相当于退费），有负权边。

**时间复杂度**：O(F × SPFA时间)，F是最大流量。

## 六、二分图匹配

### 6.1 问题描述
二分图：节点分成左右两组，边只在两组之间。求最大匹配（最多能选多少条不共享端点的边）。

应用：任务分配、工作调度、稳定婚姻。

### 6.2 匈牙利算法

**核心思想**：增广路。

**算法步骤**：
1. 对左边每个节点u：
   a. 尝试给u找一个匹配的右边节点v
   b. 如果v没被匹配，直接匹配
   c. 如果v已被匹配给u'，尝试让u'找另一个匹配（递归）
   d. 如果u'能找到新匹配，u就和v匹配，u'和新节点匹配
   e. 否则u匹配失败

**时间复杂度**：O(nm)

**关键概念**：增广路——从未匹配点出发，交替经过未匹配边和匹配边，最后到达未匹配点的路径。翻转增广路上的匹配状态，匹配数+1。

💡 **顿悟**：匈牙利算法的本质是"抢"——如果心仪的对象被抢了，就让抢的人再找一个，找不到就只能放弃。这个递归过程就是在找增广路。

### 6.3 二分图最佳匹配（KM算法）
如果边有权重，求总权重最大的完美匹配。用KM算法（Kuhn-Munkres），时间O(n³)。

## 七、网络优化的建模技巧

### 7.1 常见问题的网络流建模

| 实际问题 | 建模方法 |
|---------|---------|
| 任务分配 | 二分图匹配 / 最小费用流 |
| 项目选择（最大权闭合图） | 最大流最小割 |
| 矩阵填充 | 二分图匹配 |
| 多源多汇 | 加超级源点和超级汇点 |
| 节点有容量 | 拆点（入点→出点，边容量为节点容量） |
| 下界流 | 建辅助图，转化为普通最大流 |

### 7.2 最大流最小割定理
最大流 = 最小割。割是把节点分成S和T两组（s∈S, t∈T），割的容量是从S到T的边容量之和。

这个定理很重要：很多"最小割"问题可以转化为最大流来解。

## 八、个人研究笔记

### 💡 顿悟时刻

1. **网络优化的本质是"图上的线性规划"**：最短路、最大流、最小费用流都可以写成线性规划，但用图的特殊结构可以设计出更高效的算法。

2. **增广路是通用思想**：最大流、费用流、二分图匹配都用了增广路的思想——找到一条可以改进的路径，翻转状态。

3. **贪心不一定对，但在某些结构下对**：Dijkstra和Prim都是贪心，在非负权/无环的条件下正确；但一般的图问题贪心往往失效。

4. **并查集是被低估的数据结构**：近乎O(1)的连通性查询，Kruskal的核心。
