## 案例一：城市交通最短路径

### 问题描述
5个地点，道路和距离如下。求从地点0到地点4的最短路径。

```
    10      50
 0───→1────→2
 │    │     │
30   50     │10
 ↓    ↓     ↓
 3───→4─────┘
   20    60
```

### 代码实现
```python
import sys
sys.path.insert(0, '02_算法实现手札/00_手动实现详解')
from importlib import import_module
net = import_module('11_网络优化经典算法_手动实现')

g = net.Graph(5)
g.add_edge(0, 1, 10)
g.add_edge(0, 3, 30)
g.add_edge(0, 4, 100)
g.add_edge(1, 2, 50)
g.add_edge(2, 4, 10)
g.add_edge(3, 2, 20)
g.add_edge(3, 4, 60)

dist, prev = net.dijkstra_heap(g, 0)
path = net.get_path(prev, 0, 4)
print(f"最短路径：{'→'.join(map(str, path))}")
print(f"最短距离：{dist[4]}")
```

### 结果分析
- 最短路径：0→3→2→4，距离60
- 不是直觉上的0→1→2→4（距离70），也不是0→4直达（100）
- Dijkstra的贪心策略找到了最优路径

💡 **技巧**：交通导航是最短路的经典应用。如果道路有拥堵（动态变化），需要用动态最短路算法。

## 案例二：村村通公路（最小生成树）

### 问题描述
4个村庄要修公路连通，修路成本如下。求最小总成本。

| | 村庄1 | 村庄2 | 村庄3 | 村庄4 |
|---|-------|-------|-------|-------|
| 村庄1 | - | 1万 | 4万 | 3万 |
| 村庄2 | 1万 | - | 2万 | - |
| 村庄3 | 4万 | 2万 | - | 5万 |
| 村庄4 | 3万 | - | 5万 | - |

### 代码实现
```python
g = net.Graph(4)
g.add_edge(0, 1, 1)
g.add_edge(0, 2, 4)
g.add_edge(0, 3, 3)
g.add_edge(1, 2, 2)
g.add_edge(2, 3, 5)

w_prim, e_prim = net.prim(g)
w_kruskal, e_kruskal = net.kruskal(g)
print(f"Prim: 总成本={w_prim}万，修路方案={e_prim}")
print(f"Kruskal: 总成本={w_kruskal}万，修路方案={e_kruskal}")
```

### 结果分析
- 最小成本：6万
- 修路方案：1-2（1万）+ 2-3（2万）+ 1-4（3万）= 6万
- Prim和Kruskal得到相同结果（最小生成树可能不唯一，但总权重唯一）

💡 **技巧**：最小生成树用于"连通所有节点且总成本最小"的问题。如果要求从一个中心节点出发，那是最短路径树，不是最小生成树。

## 案例三：水管网络最大流量

### 问题描述
4个节点的水管网络，求从水源0到用户3的最大流量。

```
    3       2
 0───→1────→3
 │    ↑     ↑
2    │1    │3
 ↓    │     │
 2────┴─────┘
```

### 代码实现
```python
dinic = net.Dinic(4)
dinic.add_edge(0, 1, 3)  # 0→1，容量3
dinic.add_edge(0, 2, 2)  # 0→2，容量2
dinic.add_edge(1, 2, 1)  # 1→2，容量1
dinic.add_edge(1, 3, 2)  # 1→3，容量2
dinic.add_edge(2, 3, 3)  # 2→3，容量3

flow = dinic.max_flow(0, 3)
print(f"最大流量：{flow}")
```

### 结果分析
- 最大流量：5
- 路径1：0→1→3，流量2（受1→3容量限制）
- 路径2：0→2→3，流量2（受0→2容量限制）
- 路径3：0→1→2→3，流量1（受1→2容量限制）
- 总计：2+2+1=5

💡 **技巧**：最大流问题的关键是建图。很多看似不相关的问题（如项目选择、矩阵填充）都可以转化为最大流。

## 案例四：任务分配（二分图匹配）

### 问题描述
3个工人，3个任务。每个工人能做的任务不同。求最多能分配多少任务。

| 工人 | 能做的任务 |
|------|-----------|
| 工人0 | 任务0, 任务1 |
| 工人1 | 任务0, 任务2 |
| 工人2 | 任务1, 任务2 |

### 代码实现
```python
graph_left = [
    [0, 1],  # 工人0
    [0, 2],  # 工人1
    [1, 2],  # 工人2
]

matching, max_match = net.hungarian_bipartite_matching(graph_left, 3)
print(f"最大匹配数：{max_match}")
print(f"匹配结果（任务→工人）：{matching}")
for task, worker in enumerate(matching):
    if worker != -1:
        print(f"  任务{task} → 工人{worker}")
```

### 结果分析
- 最大匹配：3（完美匹配）
- 任务0→工人0，任务1→工人2，任务2→工人1
- 每个工人恰好做一个任务，每个任务恰好被一个人做

💡 **技巧**：二分图匹配用于"两组对象之间的配对"问题。如果边有权重（如工人做任务的效率），求最大总效率，需要用KM算法（最佳匹配）。

## 案例五：运输调度最小费用（最小费用流）

### 问题描述
两个工厂（0,1）生产产品，两个仓库（2,3）需要收货。运输有容量和费用，求最小费用的运输方案。

- 工厂0产量：3，工厂1产量：2
- 仓库2需求：2，仓库3需求：3
- 运输路线和费用：
  - 0→2：容量3，费用1
  - 0→3：容量2，费用2
  - 1→2：容量1，费用5
  - 1→3：容量3，费用1

### 代码实现
```python
# 加超级源点4和超级汇点5
mcmf = net.MinCostMaxFlow(6)
# 源点到工厂
mcmf.add_edge(4, 0, 3, 0)  # 工厂0产量3
mcmf.add_edge(4, 1, 2, 0)  # 工厂1产量2
# 工厂到仓库
mcmf.add_edge(0, 2, 3, 1)
mcmf.add_edge(0, 3, 2, 2)
mcmf.add_edge(1, 2, 1, 5)
mcmf.add_edge(1, 3, 3, 1)
# 仓库到汇点
mcmf.add_edge(2, 5, 2, 0)  # 仓库2需求2
mcmf.add_edge(3, 5, 3, 0)  # 仓库3需求3

flow, cost = mcmf.min_cost_flow(4, 5)
print(f"运输量：{flow}，最小费用：{cost}")
```

### 结果分析
- 总运输量：5（全部运完）
- 最小费用：根据具体路径计算
- 优先走路费用低的路线，再走费用高的

💡 **技巧**：最小费用流是运输调度的标准模型。多源多汇时，加超级源点和超级汇点转化为单源单汇。

## 案例六：项目选择（最大权闭合图 → 最小割）

### 问题描述
有3个项目，每个项目有收益，但需要某些技术。技术需要成本。选哪些项目净收益最大？

- 项目A：收益10万，需要技术1
- 项目B：收益20万，需要技术1、技术2
- 技术1：成本5万，技术2：成本8万

### 建模方法（最大权闭合图）
这是最大流最小割的经典应用：
1. 建超级源点s和超级汇点t
2. s→项目，容量=项目收益
3. 技术→t，容量=技术成本
4. 项目→所需技术，容量=∞
5. 最大收益 = 总项目收益 - 最小割

### 代码实现
```python
# 节点：0=s, 1=项目A, 2=项目B, 3=技术1, 4=技术2, 5=t
dinic = net.Dinic(6)
INF = float('inf')
# s→项目
dinic.add_edge(0, 1, 10)  # 项目A收益10
dinic.add_edge(0, 2, 20)  # 项目B收益20
# 技术→t
dinic.add_edge(3, 5, 5)   # 技术1成本5
dinic.add_edge(4, 5, 8)   # 技术2成本8
# 项目→技术（容量无穷大）
dinic.add_edge(1, 3, INF)  # 项目A需要技术1
dinic.add_edge(2, 3, INF)  # 项目B需要技术1
dinic.add_edge(2, 4, INF)  # 项目B需要技术2

min_cut = dinic.max_flow(0, 5)
total_profit = 10 + 20
max_profit = total_profit - min_cut
print(f"最小割：{min_cut}")
print(f"最大净收益：{max_profit}万")
```

### 结果分析
- 选项目A+B，需要技术1+2
- 收益：10+20=30万，成本：5+8=13万，净收益17万
- 或者只选项目B，需要技术1+2，收益20-13=7万
- 最优：选A+B，净收益17万

💡 **技巧**：最大权闭合图是"选项目需要前置条件"类问题的通用模型。核心是最大流最小割定理。

## 建模技巧总结

### 1. 如何判断是网络优化问题？
- 问题中有"节点"和"连接" → 可能是图论问题
- 求"最短/最小/最大" → 最短路/MST/最大流
- 有"容量限制" → 最大流/费用流
- 有"两组对象配对" → 二分图匹配

### 2. 建图技巧
| 问题特征 | 建模方法 |
|---------|---------|
| 多源多汇 | 加超级源点和超级汇点 |
| 节点有容量 | 拆点（入点→出点，边容量=节点容量） |
| 无向边 | 加两条方向相反的有向边 |
| 下界流 | 建辅助图，转化为普通最大流 |
| 项目选择 | 最大权闭合图 → 最小割 |

### 3. 算法选择
| 问题 | 首选算法 | 时间复杂度 |
|------|---------|-----------|
| 单源最短路（非负权） | Dijkstra（堆优化） | O(m log n) |
| 单源最短路（负权） | SPFA / Bellman-Ford | O(nm) |
| 全源最短路 | Floyd | O(n³) |
| 最小生成树（稠密） | Prim | O(n²) |
| 最小生成树（稀疏） | Kruskal | O(m log m) |
| 最大流 | Dinic | O(n²m) |
| 最小费用流 | SPFA+连续最短路 | O(F × nm) |
| 二分图匹配 | 匈牙利 | O(nm) |
