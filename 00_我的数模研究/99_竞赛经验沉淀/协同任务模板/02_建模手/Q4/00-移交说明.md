## 二、验证题结果速查（已知正确答案）

| 指标 | 数值 | 验证方法 |
|------|------|---------|
| （如：最小面积） | （如：30） | （如：枚举验证） |
| | | |

**编程手复算判定标准**：

| 编程手结果 | 判定 | 下一步 |
|---|---|---|
| = 已知值 | ✅ 与建模手一致，确认正确 | 跑正式数据 |
| < 已知值 | ⚠️ 检查建模手是否漏候选 | 优先验证更小值是否真可行 |
| > 已知值 | ❌ 检查实现是否有bug | 查重叠检测/边界处理 |

**关键原则**：验证题不对，不跑正式数据。

## 四、红线制度（复盘精华，绝对不能做）

> 红线是被之前的实践证伪的内容，后续问绝对不能复用。

1. ❌ **不要改模型假设**——有问题先反馈，建模手才知道假设的依据
2. ❌ **不要用浮点近似**——需要精确的地方用整数
3. ❌ **不要跳过验证题**——验证题不对，正式结果不可信
4. ❌ **不要设计新算法**——按建模手的方案实现，有更好的方案先反馈
5. ❌ **不要删除旧代码**——废弃的移到归档，留痕
6. ❌ **不要照抄参考论文参数**——参数必须与本题目标函数量纲实测匹配
7. ❌ **不要沿用已被否决的方法**——见 `建模手/实践反馈融入.md` 的否决清单

## 五、反馈方式

编程手在实现过程中发现问题，写在 `编程手/QX/理论问题反馈.md` 中：

```markdown
# QX 理论问题反馈

## 问题1：XXX
- **描述**：（什么问题）
- **复现步骤**：（怎么跑出来的）
- **期望结果**：（建模手说应该是什么）
- **实际结果**：（实际跑出来是什么）
- **建议修正**：（如果有）
```

建模手定期查看反馈，更新 `实践反馈融入.md` 和 `权威数字表.md`。
